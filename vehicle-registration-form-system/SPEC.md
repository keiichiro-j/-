# 新車新規登録依頼書 発行システム 仕様書

- 版数: v0.1（初版・実装前レビュー用）
- 位置づけ: 既存の「車両在庫管理アプリ」（ルート直下の `Code.gs` 等）とは**独立したスタンドアロンのGASプロジェクト**
- 対象ディレクトリ: `vehicle-registration-form-system/`

---

## 1. 概要

### 1.1 目的
新車新規登録の依頼書（陸運局・OSS窓口への提出書類の元となる社内依頼書）を、担当者がWebフォームから入力するだけで、
1. 依頼履歴として記録し、
2. その場でPDFとして出力できるようにする。

紙申請・OSS（電子）申請の2パターンに対応する。

### 1.2 想定利用者
- 社内の登録手続き担当者（同時に複数名がアクセスする可能性あり）

### 1.3 動作環境
- Google Apps Script（Web App としてデプロイ）
- データストア: Google スプレッドシート1冊（本システム専用、既存の車両在庫管理アプリとは別ファイル）
- PDF保存先: Google ドライブ（本システム専用フォルダ）

---

## 2. 用語

| 用語 | 説明 |
|---|---|
| 紙登録 | 従来の紙ベースでの新車新規登録申請。全車両共通の登録日を1つ指定する |
| OSS登録 | ワンストップサービス（電子）申請。車両ごとに個別の登録日を指定する |
| 依頼書 | 1回の送信（1社・1〜10台）に対して発行されるPDF。履歴シート上は `submissionId` で束ねる |
| 履歴シート | 送信された依頼内容を1車両1行で蓄積する台帳シート |

---

## 3. 全体アーキテクチャ

```
[担当者] → Webフォーム(HTML Service)
              │ google.script.run
              ▼
        processFormData(formData)
              │
   ┌──────────┼──────────────┐
   ▼          ▼              ▼
 入力検証   履歴シートへ追記   PDF生成用の一時シート作成
   (サーバー側)  (1車両1行)      │
                              テンプレートを複製 → 値を書き込み
                              → PDFエクスポート → 一時シート削除
                              → PDFをDriveの月別フォルダへ保存
                              ▼
                         PDFのURLをクライアントへ返却 → 新規タブで表示
```

### 3.1 設計方針の変更点（レビュー時の指摘を反映）
旧実装は「共通のテンプレートシートを毎回クリアして使い回す」方式だったため、同時送信時に他ユーザーのデータを上書きするリスクがあった。本仕様では、

- **依頼1件ごとに、テンプレートシートを`copyTo()`で一時シートとして複製し、複製先にのみ値を書き込む**
- PDFエクスポート完了後、一時シートを削除する
- 複製〜削除の一連の処理は `LockService.getScriptLock()` で保護し、複製時点での競合のみを短時間ロックする（PDF出力待ちの間はロックしない）

これにより、複数人が同時に送信してもデータが混在しない。

## 4. 機能要件

### 4.1 入力画面

| 項目 | 入力方式 | 備考 |
|---|---|---|
| 出力フォーマット | プルダウン（OSS / 紙） | 選択により以下のUIが動的に切替 |
| 依頼会社名 | コンボボックス（`<datalist>`：自由入力＋履歴からの候補サジェスト） | 履歴シートに登場した会社名をサジェスト候補として自動収集 |
| 担当責任者 | コンボボックス（同上） | 同上 |
| 送付日 | 日付ピッカー | 必須 |
| 登録日（全体） | 日付ピッカー | 「紙」選択時のみ表示・必須 |

**車両データテーブル（最大10台、行単位で追加・削除可能）**

| 項目 | 入力方式 | 備考 |
|---|---|---|
| 登録日（個別） | 日付ピッカー | 「OSS」選択時のみ表示・必須（行内に入力がある場合） |
| 使用車名 | コンボボックス（履歴からサジェスト） | |
| 車台番号（下4桁） | テキスト（4桁数字のみ、`pattern`+サーバー側検証） | |
| 型式 | テキスト | |
| 類別番号 | テキスト | |
| 自動車税 / 環境性能割 / 重量税 | 数値入力（0以上の整数、円） | |
| 希望ナンバー / 予備検登録車 / 本検登録車 / 身障者減免車 | プルダウン（空欄 / 〇） | |
| 担当者 | コンボボックス（履歴からサジェスト） | |

**UI上の工夫**
- 車両行は初期3行表示＋「行を追加」ボタンで増やす（旧実装の固定10行表示はスクロールが長く使いにくいため変更）
- 未入力必須項目は送信前にクライアント側でハイライト、サーバー側でも再検証
- 送信中はボタンを無効化しプログレス表示、完了後はPDFプレビューリンクとダウンロードボタンを表示
- レスポンシブ対応（スマホ・タブレットでも車両テーブルが横スクロールで操作可能）

### 4.2 送信処理（サーバー側）
1. 必須項目・型（数値/日付/桁数）をサーバー側で検証。不正な場合は明確なエラーメッセージを返し、シートへの書き込みは一切行わない
2. `LockService` でロックを取得し、テンプレートシート（OSS用/紙用）を一時シートとして複製
3. 一時シートに共通項目・車両データを書き込み、ロックを解放
4. 一時シートをPDFエクスポート
5. PDFをDriveの `依頼書PDF/yyyy-MM/` フォルダへ保存（フォルダが無ければ自動作成）
6. 一時シートを削除
7. 履歴シートへ、車両1台につき1行で追記（`submissionId` で同一送信をグルーピング）
8. PDFのURLをクライアントへ返却

### 4.3 履歴シート
1行 = 1車両。列構成は現行実装を踏襲しつつ、日付列の型を統一する。

| 列 | 内容 | 型 |
|---|---|---|
| A | 送信日時 | Date |
| B | submissionId | 文字列（UUID） |
| C | 種別（OSS/紙） | 文字列 |
| D | 依頼会社名 | 文字列 |
| E | 担当責任者 | 文字列 |
| F | 登録日 | **Date型に統一**（旧実装ではOSS/紙で文字列フォーマットが不統一だった点を修正） |
| G | 送付日 | Date |
| H | 車両No.（送信内の連番） | 数値 |
| I〜T | 使用車名〜担当者 | 各項目 |

### 4.4 PDF出力
- ファイル名: `登録依頼書_{OSS or 紙}_{会社名}_{yyyyMMdd_HHmmss}.pdf`
- 保存先: 月別フォルダ（検索・整理性の確保。旧実装のDriveルート直置きから変更）
- エクスポート後、実データが反映されているかを確認してから一時シートを削除する（`SpreadsheetApp.flush()` に加え、エクスポート成功レスポンスを確認）

## 5. 非機能要件

| 項目 | 方針 |
|---|---|
| 同時実行制御 | `LockService` によりテンプレート複製処理のみを排他化。長時間ロックしない |
| 入力検証 | クライアント側・サーバー側の二重チェック（サーバー側を正とする） |
| エラーハンドリング | 検証エラー・PDF生成エラーを判別し、ユーザーに分かりやすい日本語メッセージを返す。部分書き込みが残らないようにする |
| アクセス制御 | Web App のデプロイ設定を「組織内のみ」とし、閲覧者を限定する（`appsscript.json` で明示） |
| 監査性 | 履歴シートに送信日時・submissionIdを必ず記録し、後から追跡可能にする |

## 6. 画面デザイン方針（モダンビジュアル）

- **配色**: ベースは白〜薄いグレーの背景、アクセントカラー1色（例: ブルー系）を強調（ボタン・見出し・選択中タブ）
- **レイアウト**: カード型UI。入力エリアと車両テーブルを視覚的に分離し、余白を広めに取る
- **タイポグラフィ**: 見出しと本文でウェイト差をつけ、日本語可読性を優先したフォントスタック
- **フィードバック**: 送信ボタンにローディングスピナー、成功時はチェックマークアイコン付きの完了メッセージ
- **入力補助**: コンボボックス（`<datalist>`）による過去入力候補のサジェストで、プルダウン的な選びやすさと自由入力の柔軟性を両立
- **レスポンシブ**: 車両テーブルは横スクロールコンテナ化し、スマホでも操作可能

## 7. スコープ外（本フェーズでは対応しない）

- 依頼履歴の検索・一覧閲覧画面（将来拡張候補）
- 依頼の承認フロー・複数担当者間のステータス管理
- 車両在庫管理アプリとのデータ連携
- OSS電子申請の外部システムへの直接連携（本システムはあくまで社内依頼書の発行まで）
