# ぎふクエスト 設計書（Claude Code向け）
## 1. 概要
岐阜県の名所を舞台にした横スクロールアクション「ぎふクエスト 〜六つの宝珠〜」を、市販インディーゲームと並べられる品質で作る。試作版（index.html 1ファイル・約1,800行）の遊びの骨格を引き継ぎ、ステージは手作り、絵と動きと手触りを作り込む。
### 前提条件
- 配信：Google Apps Script のWebアプリ。サーバー処理はセーブとランキングのみ
- 描画：素のCanvas 2D（外部ライブラリなし、外部通信なしで動く）
- 対象：PC（キーボード・ゲームパッド）とスマホ横向き（タッチ）
- 解像度：論理解像度の高さ540、横幅960～1200で画面比に追従、1タイル＝36ドット
- 舞台：岐阜県の名所をモチーフにしたフィクション。実在の店名・企業名・商標は使わない
- 権利：任天堂作品のキャラクター、見た目、音楽、名称は使わない。遊びの構造のみ参考にする
### 品質目標
| 項目 | 目標 |
|---|---|
| フレームレート | PC 60fps固定、中位スマホ 60fps（最低45fps） |
| 入力遅延 | キーを押してから動き始めるまで1フレーム以内 |
| プレイ時間 | 初回クリアまで約90分、さるぼぼ全収集で約3時間 |
| 起動時間 | タイトル表示まで2秒以内（絵の事前描画は分割して裏で行う） |
| 難しさ | 1面は初心者が約5分でクリア。6面は慣れた人でも数回のミスを想定 |

### 試作版から引き上げる点
| 試作版 | 本番版 |
|---|---|
| ステージを乱数で自動生成 | 各ステージを手作り（JSONのレベルデータ）。各ステージは4エリア構成 |
| 絵を毎フレームコードで描く | 起動時にスプライトシートへ書き出して描画を軽くする。PNG素材に差し替え可能 |
| キャラの動きは関節を三角関数で揺らすだけ | 種類ごとのキーフレームアニメーション、伸び縮み、残像 |
| 平らな地面と段差のみ | 坂道（45度・22.5度）、天井、縦スクロール、隠し部屋 |
| 音なし | 効果音とBGMをWeb Audioで合成（初期はオフ、設定でオン） |
| ボスは1フェーズ強化のみ | 3フェーズ構成、登場・撃破の演出、弱点の予告動作 |

## 2. 技術アーキテクチャ

### メインループ
- 入力を「操作コマンド」に変換（キーボード、ゲームパッド、タッチを同じ形に揃える）
- ゲームの更新は固定ステップ120Hz（アキュムレータ方式、最大8ステップ/フレーム）。どの端末でもジャンプの高さが同じになる
- 描画は前後のステップ間を補間して滑らかにする
- ヒットストップ（攻撃が当たった瞬間の一瞬停止）とスロー演出は「ゲーム内時間の倍率」で実現する
### 描画の層（奥から手前）
| 層 | 内容 | スクロール速度 |
|---|---|---|
| 空 | 時間帯と天気で変わるグラデーション、太陽・月・星 | 0 |
| 雲 | 3層の雲（流れる速さが異なる） | 0.03～0.1 |
| 遠景 | 山並み・名所のシルエット（岐阜城、北アルプス） | 0.12 |
| 中景１・２ | 森、町並み、川 | 0.3・0.5 |
| 後景の小物 | 木、灯籠、家、看板（当たり判定なし） | 1.0 |
| タイルとキャラ | 地形、敵、主人公、アイテム | 1.0 |
| 前景 | 草むら、枝、雨だれ（半透明でキャラを隠さない） | 1.3 |
| 光と天気 | 暗さ、灯り、雨・雪・霧、色調補正 | — |
| UI | HUD、メニュー、タッチボタン | — |

### 絵（アセット）の方針
- 初版は、試作版と同じく絵をコードで描く。ただし毎フレーム描くのではなく、起動時にアニメーションの各コマを2倍解像度でスプライトシートに書き出し、描画時は画像を貼るだけにする
- 素材の差し替え口： assets/ に同名のPNGシートとJSON（コマの位置）を置くと、ビルド時にBase64で埋め込まれ、コード描画より優先される。イラストレーターに発注した絵に後から差し替えられる
- GASのHTMLが大きくなりすぎないよう、PNG素材は1枚2048×2048以内、合計の容量はビルド時に表示する
### 性能の予算
- 画面内のタイルは「チャンク（16×16タイル）単位で画像に焼き付け」、変化したチャンクだけ描き直す
- 画面外の敵は動かさない（画面端から左右に1画面分の範囲だけ更新）
- パーティクルは最大800個、天気の粒は最大300個。低品質設定では半分
- キャンバスのピクセル比は最大2（低品質は1）
## 3. 画面の流れ
(図: 画面の流れ · 9画面 — タイトル→オープニング→キャラ選択→ワールドマップ→ステージ→ボス戦→結果→マップ。6面後エンディング、ハート0でゲームオーバー→マップ)

ステージは何度でも遊び直せる。タイトルの「つづき」はワールドマップから始まり、オープニングは2回目以降は自動で飛ばす。一時停止メニューからもマップへ戻れる。各画面は scenes/ 以下の1ファイルで、`enter()` `update(dt)` `draw()` `exit()` の4つの関数を持つ。

| ミナモ | 長良川の鵜匠の娘 | 3 | 5 | 2 | 2（3） | 鵜飛ばし：近くの敵を追いかける鳥 | ジャンプ長押しで滑空。水中でも速く泳げる |

| 能力 | 計算式 | 1の時 | 5の時 |
|---|---|---|---|
| 歩きの最高速度 | 168＋速さ×19（ドット/秒） | 187 | 263 |
| ダッシュの最高速度 | 歩き×1.55 | 290 | 408 |
| ジャンプ初速 | 560＋ジャンプ×32 | 592 | 720 |

### キャラごとのアニメーション（各キャラ15種類・計約80コマ）
待機（呼吸）、歩き、走り、ブレーキ（切り返し）、ジャンプ上昇・頂点・落下、着地、しゃがみ、壁に張り付く、攻撃（2種）、被弾、勝利ポーズ、放置時の仕草（3秒以上操作しないと、キャラごとに異なる動き）。着地とジャンプの瞬間は体を縦横に伸び縮みさせる。
**追加キャラ（クリア後に解放、任意）**：さるぼぼを全部集めると「さるぼぼ」自身が使える。能力は全部4、技は4人の技を順に切り替え。
## 5. 操作と物理
手触りの良さを最優先にする。下の数値は初期値で、すべて config.js にまとめ、デバッグ画面（F1キー）から遊びながら調整できるようにする。
### ジャンプと移動
| 項目 | 初期値 | 狙い |
|---|---|---|
| 上昇中の重力（ボタン押しっぱなし） | 1,320 ドット/秒² | 長押しで高く跳べる |
| 上昇中の重力（離した後）・落下中 | 2,550 ドット/秒² | 短く押すと低く跳ぶ。落下は重めに |
| 頂点付近の重力 | 速度±90以内は0.6倍 | 頂点で少しふわっとして狙いやすく |
| 落下の最大速度 | 860 ドット/秒 |  |
| 崖から落ちた後も跳べる猶予 | 0.10秒 | 「押したのに跳ばない」をなくす |
| 着地前の先行入力 | 0.13秒 | 着地の瞬間に跳ぶ |
| 頭をぶつけた時の角の補正 | 端から6ドット以内なら横にずらす | ブロックの角に引っかからない |
| 切り返しの加速 | 通常の2倍 | ブレーキが利き、砂ぼこりが出る |
| 空中の加速 | 地上の0.75倍 | 空中でも少し軽道修正できる |
| 敵を踏んだ時の跳ね返り | 押しっぱなし660、離すと420 | 連続踏みで得点が倍々に |

### 当たり判定
- 地形：タイルごとの種類（固い、上からだけ乗れる、坂（45度・22.5度）、氷、トゲ、水、溶岩）を持ち、縦と横を分けて解決する。坂では速度を保ったまま沿って移動する
- 主人公の当たり箱：幅24×高さ44。敵から受ける当たり箱は一回り小さく（上下左右4ドット狭め）して理不尽な被弾を減らす
- 踏みつけ判定：落下中で、前のフレームの足元が敵の上端＋12ドットより上にあれば踏んだことにする
- 動く床：乗っている間は床の移動量をそのまま主人公に加える。床から跳ぶと床の勢いも引き継ぐ
### カメラ
- 横：進行方向に画面の12%先読み。向きを変えた時は0.4秒かけて滑らかに切り替える
- 縦：縦に長いエリアでのみ追従。着地した時にだけ高さを合わせる（ジャンプのたびに画面が揺れない）
- ボス部屋、隠し部屋ではカメラを固定し、入った瞬間に滑らかに移動する
- 画面の揺れは大きさと時間で指定し、設定で「揺れを弱く」できる
### 操作の割り当て
| 操作 | PC | ゲームパッド | スマホ |
|---|---|---|---|
| 移動 | ←→ / AD | 左スティック・十字キー | 左下の左右パッド |
| しゃがむ・隠し通路に入る | ↓ / S | 下 | パッドを下にスライド |
| ジャンプ | Z / Space | A | 右下の大ボタン |
| 技（押しっぱなしでダッシュ） | X / Shift | B・X | 右下の小ボタン |
| 一時停止 | Esc | スタート | 右上のボタン |

スマホのボタンは位置と大きさを設定画面で動かせる。パッドは指を置いたまま左右にスライドして向きを切り替えられる。

|---|---|---|---|---|---|

| 3 | 郡上八幡 | 昼／雨・雷雨・晴れ | 水路と水門（スイッチで水位が上下する） | 郡上踊りの太鼓に合わせて動く足場、石畳と石垣 | 提灯おばけ、踊りうちわ、下駄投げ |

### 各ステージに必ず入れるもの
- 中間地点：2か所（展開の前、ボス部屋の前）
- さるぼぼ：3個。「見えているが取り方を考えるもの」「隠し部屋の奥」「キャラの能力があると楽に取れるもの」を各種1個
- 隠し部屋：1～2か所。入口は空のブロック、ひび割れの壁、滑り台の先などに隠す
- 飛騨牛串（無敵アイテム）：1個。無敵の間に敵を一掃できる敵の密集地帯の前に置く
- その土地の名物・名所の看板：各エリアに1つ。調べると短い説明文（どれも事実に基づく記述。文面は公開前に確認する）
### レベルデザインのルール（エディタで自動チェック）
- 最も跳べないゲンでも越えられること：穴は幅4タイル以内、段差は高さ3タイル以内（それを超える場所は動く床か足場を置く）
- 画面外から急に当たる敵を置かない。落ちると即ミスの穴の先には、必ず着地できる平らな場所を置く
- 新しいギミックは「失敗してもミスにならない場所」で初めて見せる
- コインの並びで「跳ぶべき軌道」を示す
- エディタ（tools/level-editor.html）でタイル・敵・アイテムを配置し、保存時に上のルールを自動検査する。試作版の validateStage を拡張して使う

| 動き | 踏める | 内容 |
|---|---|---|
| 歩く | ○ | 壁で折り返す。崖から落ちる |
| トゲ | × | 崖で折り返す。技でのみ倒せる |
| 跳ねる | ○ | 主人公に向かって跳ぶ |
| 飛ぶ | ○ | 波のように上下しながら巡回 |

## 7. ボス設計
ボスは各ステージ最後のアリーナ（幅30タイル、画面固定）で戦う。全ボス共通で3段階（HP残り100％→66％→33％で段階が上がる）。段階が上がるたびに短い演出（怒りのポーズ＋画面の揺れ、0.8秒は無敵）を入れ、攻撃が速く・多くなる。
### 全ボス共通のルール
- 攻撃の前には必ず予告がある（0.4〜0.8秒の溜めポーズ、地面の影、光る目など）。予告なしの攻撃は作らない
- 弱点は「踏む」「技を当てる」のどちらでも攻撃できる。踏むと1ダメージ（ゲンは2）、技は各キャラの技の威力どおり
- 被弾後は1.0秒の無敵（点滅）。同じ技の連続ヒットで瞬殺されないようにする
- 登場演出：名前と二つ名を大きく表示（2秒、ボタンで飛ばせる）
- 撃破演出：スローモーション（0.5秒）→ 爆発の粒子 → 「玉」が出現し、取るとクリア
- HPバーは画面上部に表示。段階の区切りに目盛り

|---|---|---|---|---|---|---|
| 1 | 大ムササビ（金華山） | 8 | 木から木へ滑空し、体当たり | 滑空中にどんぐりを3つばらまく | 画面外から高速で急降下（地面に影の予告） | 着地して休む1.5秒の間に踏む |
| 2 | 大山椒魚（長良川） | 10 | 水中から顔を出して噛みつく | 水しぶきの弾を扇状に3発 | 水位が上がり、浮き足場の上で戦う | 噛みつき後に陸に上がった背中を踏む |
| 3 | 踊り神（郡上） | 10 | 輪になって踊りながら移動、扇子を投げる | 分身2体（本体だけ影がある） | 太鼓の音に合わせて床が光り、光った床で攻撃 | 本体の頭を踏む。踊りの一拍休みが隙 |
| 4 | からくり屋台（高山） | 12 | 左右に走り、上の人形が矢を射る | からくり人形が飛び出して追ってくる | 屋台が二段に変形し、上下から攻撃 | 屋台の上に乗り、人形の頭を踏む（乗ると運ばれる） |
| 5 | 雪鬼（白川郷） | 12 | 雪玉を転がす（転がるうちに大きくなる） | つららを天井から落とす | 吹雪で視界を白く、横風で押し戻す | 雪玉を投げた直後の硬直に背後から攻撃 |
| 6 | 乗鞍の火竜（奥飛騨） | 16 | 溶岩から飛び出して火の玉 | 炎の息を横一直線に（上か下に逃げる） | 足場が崩れ、溶岩が上がる中で戦う | 息を吐いた後に下がる頭を踏む |

### ボスの作り方（コード）
- 1体＝1ファイル（src/bosses/musasabi.js など）。共通の基底クラス Boss に「状態（待機・予告・攻撃・隙・被弾・段階変化・撃破）」の状態機械を持たせ、各ボスは状態ごとの動きと描画だけを書く
- 攻撃パターンは表（データ）で持ち、段階ごとに「使う技」「速度の倍率」「待ち時間」を変える
- 試作版のボス（makeBoss / updateBoss / drawBoss）の動き・当たり判定を引き継いで、段階3と予告演出を足す
- 難易度「やさしい」ではボスのHPを×0.7、待ち時間を×1.3にする
## 8. 天気・時間帯・グラフィック品質
### 天気（遊びにも影響する）
| 天気 | 見た目 | 遊びへの影響 |
|---|---|---|
| 晴れ | 光の筋、くっきりした影 | なし（基準） |
| くもり | 空が灰色、全体を少し暗く | なし |
| 雨 | 斜めに降る雨粒、水たまりの波紋、地面が濡れて反射 | 地面が少し滑る（減速0.9倍） |
| 雷雨 | 雨＋稲光で一瞬画面が白く光る | 稲光の瞬間だけ暗い場所が見える。落雷の予告マーク→落雷（ステージ3・6のみ） |
| 霧 | 奥の背景がかすみ、手前に霧の帯が流れる | 遠くの敵が見えにくい（ヒントとしてシルエットを薄く表示） |
| 雪 | 大小の雪片、地面に積もる | 足跡が残る（見た目のみ） |
| 吹雪 | 横殴りの雪、視界の端が白い | 一定間隔で横風（進む向きによって速くなる・遅くなる） |
| 火山灰 | 灰色の粒子、赤い空、遠くの噴煙 | なし（ステージ6の雰囲気づくり） |

- 各ステージは「使う天気の候補」を持ち、エリアの切り替えや一定時間ごとに次の天気へ移る
- 天気の切り替えは3〜5秒かけて少しずつ混ぜる（雨粒の量、空の色、明るさを同時に変える）
- 粒子は上限を決めて使い回す（雨300粒、雪250粒）。スマホでは半分に減らす
### 時間帯
- 昼・夕暮れ・夜・夜祭りの4種類。空のグラデーション、背景の色味、全体の明るさを一括で変える
- 夜は「光の穴」方式（試作版の drawLighting）：暗い膜を画面に重ね、提灯・篝火・主人公の周りだけ穴を開けて明るく見せる。膜は画面の半分の解像度で作り、拡大して重ねる
- ステージ2・4は進むと時間が流れる（夕暮れ→夜）
### グラフィックを試作版より上げる方法
- **絵素材の一括画像（アトラス）**：起動時にキャラ・敵・タイル・小物をすべて画面外のキャンバスに描いて1枚にまとめ、ゲーム中はそこから切り出して貼るだけにする。毎フレーム図形を描かないので速い
- **キャラのアニメ**：各キャラに待機4・走り8・ジャンプ3・落下2・被弾2・技4コマ以上。着地時の縦つぶれ、走り出しの土ぼこりを入れる
- **背景の多重スクロール**：遠景（山並み）、中景（町・森）、近景（木・建物）、手前（画面手前をぼかした草や柵）の4層以上。それぞれ違う速さで流す
- **タイルの継ぎ目**：地面の端・角・内角を自動で選んで描く（隣のタイルを見て形を決める）。草の縁、石垣の目地、屋根瓦の重なりまで描く
- **光と影**：主人公・敵の足元に楕円の影。晴れの日は背景に光の筋
- **手応えの演出**：踏んだ瞬間に0.05秒止める、画面を揺らす、白く光らせる、星や葉の粒子を飛ばす
- **画面の後処理**：画面端を少し暗くする（ビネット）。天気に合わせた色味の重ね塗り（雨は青み、夕暮れは橙）
- **性能の目安**：PCで60fps、スマホ（中価格帯）で50fps以上。足りない場合は「画質：低」で粒子半分、手前の層と後処理を省く
## 9. UI・演出・サウンド・セーブ
### プレイ中の表示（HUD）
- 左上：キャラの顔アイコン、ハート、技の溜まり具合（丸いゲージ）
- 上中央：コイン数、さるぼぼ（3つの枠。取ると埋まる）、経過時間
- 右上：一時停止ボタン、天気アイコン
- ボス戦：上部にボス名とHPバー
- スマホ：左下に左右ボタン、右下にジャンプ・技・ダッシュ。ボタンの大きさと位置は設定で変えられる。半透明で、押している間は濃くなる
### メニュー画面
- 一時停止：続ける / やり直す / マップへ戻る / 設定
- 設定：音（初期は無音）・効果音とBGMの音量、画質（高/低/自動）、画面の揺れ（入/切）、難易度（やさしい/ふつう）、ボタン配置、キー設定
- 図鑑：集めたさるぼぼ、倒した敵、見た名物看板を一覧で見られる
- 結果画面：クリア時間、コイン、さるぼぼ、ミスの回数。自己ベスト更新時は「NEW」
### 画面の切り替えと演出
- 画面切り替えは丸く絞る（アイリス）か、横に拭う動き。0.4秒以内
- ステージ開始時にステージ名と天気を大きく表示
- オープニングとエンディングは、絵＋文字の紙芸居風。いつでも飛ばせる
### サウンド（初期は無音）
- 音声ファイルは使わず、ブラウザの音の機能（Web Audio）でその場で音を作る（ジャンプ、コイン、踏む、被弾、ボス撃破など）
- BGMは短い旋律をデータで持って繰り返す。ステージごとに和風の音階を使う
- 設定で音を「入」にしたときだけ鳴らす（スマホは画面を触った後でないと鳴らせないため）
### セーブ
- ブラウザの端末内に保存（localStorage）。保存名は gq2_save。保存できない環境でもゲームは止めない
- 中身：版番号、クリアしたステージ、各ステージのさるぼぼ（3つの取得有無）、ベストタイム、持ちコイン、解放したキャラ、設定
- 版番号を見て古いデータを新しい形に変換する関数を用意する
- 将来の拡張：GAS側（PropertiesService の UserProperties）にも保存して、別の端末でも続きができるようにする（必須ではない）
### やり込み要素
- さるぼぼを18個全部集めると「うらステージ」解放
- 全ステージに目標タイム。達成でマップに金の印
- 隠しキャラ：特定の条件（例：全ボスをノーミスで倒す）で解放
## 10. 開発フェーズとClaude Codeへの依頼方法
Claude Codeには一度に全部を頼まず、下のフェーズごとに依頼して、その都度「完了の条件」を満たしたか確認してから次へ進む。
| フェーズ | 作るもの | 完了の条件 |
|---|---|---|
| 0 土台 | フォルダ構成、組み立てスクリプト（src → 1つの index.html）、ゲームの土台（画面管理・入力・カメラ）、自動テストの仕組み | GASに貼って開くと空のステージで四角が動かせる。PC・スマホ両方で操作できる |
| 1 操作と物理 | 主人公4人の動き・技、タイルと当たり判定、坂、通り抜け足場、動く床 | テスト用の練習ステージで全キャラが設計どおりに動く。60fpsを保つ |
| 2 ステージ1完成 | 金華山ステージ一式（絵・敵・天気・ボス）、レベルエディタ | ステージ1を最初からボス撃破まで遊べる。ここで品質の基準を確定させる |
| 3 ステージ2〜6 | 残り5ステージとボス5体、各ギミック | 全ステージが自動検査に合格し、全ボスを倒せる |
| 4 画面の流れ | タイトル、オープニング、キャラ選択、ワールドマップ、結果、エンディング、セーブ | 最初からエンディングまで通して遊べ、途中で閉じても続きから遊べる |
| 5 仕上げ | 演出、サウンド、設定、図鑑、うらステージ、画質の自動調整 | 中価格帯のスマホ実機で50fps以上。社内テストプレイで出た不具合をすべて直す |

### CLAUDE.md（リポジトリ直下に置くルール書）
```
# ぎふクエスト 開発ルール

## 必ず守ること
- 実行環境は Google Apps Script の HtmlService。最終成果物は Code.gs と index.html の2ファイルのみ
- 描画は Canvas 2D。外部ライブラリ・外部画像・外部音声・CDNは使わない（絵も音もコードで作る）
- index.html は build スクリプトで src/ から組み立てる。index.html を直接編集しない
- 任天堂等の既存作品のキャラ・名前・デザイン・音楽を真似しない。土管、キノコで巨大化、？ブロック、旗ざおちのゴールは使わない
- 岐阜の地名・名物は題材として使うが、地図は架空。タイトル画面に「この作品はフィクションです」を表示する
- PCで60fps、スマホで50fps以上。毎フレームの新しい配列・オブジェクトの作成は避ける
- 物理は固定ステップ（1/120秒）で計算し、描画と分ける

## 作業の進め方
- 設計書（docs/design.md）の数値・仕様に従う。変える必要があれば理由を書いて提案する
- 調整用の数値は src/data/ にまとめ、コードに直接書かない
- 変更のたびに npm test（ヘッドレスChromeの自動テスト）を通す。コンソールエラー0件
- フェーズの終わりに、PCとスマホ幅の画面写真を screenshots/ に保存する
```

### 依頼文の例（フェーズ0・1）
添付の設計書（docs/design.md）と試作版（reference/prototype.html）を読んで、フェーズ0とフェーズ1を実装してください。試作版の物理（moveBody、コヨーテタイム、ジャンプ先行入力）とキャラの数値はそのまま引き継ぎ、設計書の「5. 操作と物理」にある坂と通り抜け足場を追加してください。完了の条件は設計書「10. 開発フェーズ」の表のとおりです。完了したら、動作確認の結果と画面写真、設計から変えた点を報告してください。
フェーズ2以降も同じ形で、「どの章を実装するか」「完了の条件」「報告してほしいこと」を書いて依頼する。試作版の index.html は参考資料として一緒に渡す。
