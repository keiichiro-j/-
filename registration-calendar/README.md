# 登録カレンダー（AU NEW CAR 登録カレンダー）

車両登録スケジュールを管理するGoogle Apps Script製Webアプリです。GoogleスプレッドシートをDBとし、月ごとにシートを分けて保存します。

## 今回のアップデート内容

### 1. 編集権限をGoogleアカウントで判別
これまでは `k-toda@gifuyanase.co.jp` 一人だけが編集可能で、しかも共有パスワード（平文でコード内にハードコード）が実質使われていない状態でした。

- `Code.gs` の `EDITOR_EMAILS` 配列に登録したGoogleアカウントだけが登録・編集できるようにしました。
- 編集権限の判定は必ずサーバー側（`saveRecord`）で `Session.getActiveUser().getEmail()` を見て行います。画面側のボタン非表示などはあくまで見た目の制御で、実際の権限チェックはサーバー側が最終防衛線です。
- 画面右上（スマホはヘッダー下）に、現在アクセスしているGoogleアカウントと「編集可 / 閲覧のみ」が常に表示されます。
- 閲覧のみのアカウントでは、新規登録の入口（＋新規登録、日付クリック、ドラッグ&ドロップ）が出ず、既存データはクリックすると「閲覧のみ」の詳細モーダル（全項目readonly・保存ボタン非表示）が開きます。

**編集者の追加/削除方法**: `Code.gs` の `EDITOR_EMAILS` にメールアドレスを追記・削除して `clasp push` / デプロイし直してください。パスワードは廃止したので、以前の `ADMIN_PASSWORD` は無効です（このコードがリポジトリに入る前の運用で使われていたパスワードは漏洩済み扱いとして、今後使用しないでください）。

**デプロイ時の注意**: `appsscript.json` は `executeAs: USER_ACCESSING` にしています。これは各ユーザーのGoogleアカウントを正しく判定するために必須の設定です（`USER_DEPLOYING` のままだと全員が同じ権限で動いてしまいます）。Webアプリのデプロイ設定でも「アクセスできるユーザー」を組織内（ドメイン）に限定してください。匿名アクセスを許可すると `Session.getActiveUser().getEmail()` が取得できず、誰も編集できなくなります。

### 2. 「見づらい」の原因調査と改善
複数の方から「見づらい」という声があったため、UIを見直しました。主な原因と対処は以下の通りです。

| 原因 | 内容 | 対処 |
|---|---|---|
| 文字が小さすぎる | 顧客名・拠点・KPIラベルなどが `7px〜9px` で組まれており、老眼や離れた画面では判読が困難 | 最小サイズを `10px` 前後まで底上げし、顧客名やKPIの数値などの主要情報は `text-sm`（14px）〜 `text-2xl/3xl` に拡大 |
| 文字間が広すぎる | 小さい英字ラベルに `tracking-[0.2em]〜[0.25em]` を使っており、余計に間延びして見えた | `tracking-wide` 程度まで縮小 |
| コントラスト不足 | ラベルやカードの補助情報が薄いグレー（`#80868B`/`#70757A`）で、視認性が低かった | `#3C4043` など濃いグレーに変更し、太字も併用 |
| 情報密度が高すぎる | カレンダーの登録カードが高さ74px前後に4行分の情報を詰め込み、拡大すると窮屈で崩れる | カード高さ・カレンダーセルの最小高さを拡張し、拡大後のテキストが収まるように調整 |
| OSS/紙登録が色だけで区別 | 色弱の方や離れた画面では判別しづらい | バッジに `⚡OSS` / `📄PAPER` のようにアイコン＋文言を併記し、色以外でも区別できるように |
| 通信失敗が無言 | データ取得（`fetchData`）が失敗しても画面が空のままで気づけなかった | 取得失敗時にエラーメッセージを表示するようにした |

見た目のブランドロゴ表示も、これまでJavaScriptでヘッダーの文字をDOM操作で書き換える作りだったため、HTML側に直接「AU NEW CAR」を記載する形に整理しました。

### 3. カレンダーのマスが登録件数で詰まる問題
1マスに2件以上入るとカード同士が窮屈になり、内側スクロールで見るしかなかった点を改善しました。

- カレンダーの1マスの高さは登録件数によらず常に固定です。
- 1件だけの日はこれまで通りの詳細カードをそのまま表示します。
- 2件以上ある日は、1件目をコンパクトなカードで表示し、残りは「+N件 すべて見る」ボタンにまとめました。ボタンを押すとその日の全件を一覧できるモーダルが開き（`openDayListModal`）、各カードから通常の編集モーダルにもそのまま遷移できます。

### 4. 未定リストのカードの余白を詰めた
右サイドバー（未定リスト）のカードは高さ固定＋余白多めの作りだったため、固定高さをやめて内容に合わせた余白（`px-3 py-2` ＋ 行間 `gap-1`）に詰め、カード間の間隔も `gap-2` → `gap-1.5` にしました。

### 5. カレンダー／リスト／未定リストの高さを揃え、内部スクロールに統一
カレンダー・リスト表示・未定リストがそれぞれ別の高さで伸び縮みしており、ページ全体がスクロールしてしまう場合がありました。

- カレンダー表示の外枠（`calendar-wrapper`）を `lg:h-[820px]` の固定高さにしました。リスト表示（`view-list-container`）・未定リスト（`sidebar-wrapper`）も同じ高さで揃います。
- それぞれの中身（カレンダーのマス目、リストのテーブル、未定リストのカード）は、この固定高さを超えた分だけ内部スクロールします。ページ自体がその分で伸びることはありません（ヘッダーやダッシュボード部分を含めたページ全体のスクロールは従来どおりです）。
- 対象はPC相当の画面幅（`lg:` = 1024px以上、未定リストが横に並ぶ幅）です。それより狭い画面は今までどおり縦積みの自然な高さのままです。

### 6. 「登録台数」に当月の未定リスト分も含めるように
これまでは登録日が確定した分のみを台数としてカウントしていましたが、今月分の確定台数に加えて、登録日未定（まだ日付が決まっていない）の全件も合算して「登録台数」に表示するようにしました。日付がないため月では絞り込めず、未定分は常に全件を加算します。OSS登録率・OSS登録件数・紙登録件数・拠点別の件数も同じ集計範囲（今月確定分＋未定分）に揃えています。

### 7. PDFリンクを日付に関わらず即反映、月フォルダで誤マッチを防止
- これまでフロント側で「登録日が過去の分だけ」PDFアイコン・PDFへのリンクを表示する作りだったため、実際にはリンクが貼られていても今日以降の日付では見えませんでした。日付に関わらず、リンクが貼られていればカレンダー・リストどちらでもPDFアイコンが表示され、クリックでPDFを開けるようにしました（アイコン以外の部分をクリックすると、これまでどおり編集/詳細モーダルが開きます）。
- `autoLinkVehicleInspectionPDF`（Code.gs）の突き合わせロジックを、部分一致から正規化した氏名の完全一致に変更しました。「山田高」と「山田高市」のような別人を誤って同一視しないようにするためです。
- 車検証PDFの保管フォルダが `2026.08` のような年.月フォルダで分かれている前提で、同姓同名の別人がいる場合は登録予定日が属する月フォルダのPDFを優先して採用します。月フォルダで絞り込めず候補が複数残る場合は、誤リンクを避けるためリンクを空のままにします（すでにリンク済みの行は上書きしません）。
- `autoLinkVehicleInspectionPDF` を15分おきに自動実行するトリガーを追加しました（`setupPdfLinkTrigger`）。GASエディタからこの関数を一度だけ手動実行してトリガーを設置してください。これにより、ドライブにPDFが追加されてから最大15分程度でアプリ側に反映されます。

### 8. ダッシュボードのラベルを日本語表記に変更
「TOTAL REGISTRATIONS」「OSS RATE」「OSS COMPLETED」「PAPER PROCESS」を、それぞれ「登録台数」「OSS登録率」「OSS登録件数」「紙登録件数」に変更しました。単位表記も「UNITS」「CASES」→「台」「件」に揃えています。

### 9. 未定リストからの登録日反映で重複が起きないように
未定リストのカードをカレンダーへドラッグ&ドロップして登録日を反映する処理（`handleDrop`）が、顧客名の文字列一致で対象データを探していたのが原因でした。同姓同名の別レコード（別人の場合はもちろん、リピート客の別案件なども含む）が既に存在すると、ドラッグした本人ではなく別のレコードを誤って更新してしまうことがありました。

- ドラッグ&ドロップは顧客名ではなくレコードのID（ドラッグ開始時に `dataTransfer` へ載せる値をIDに変更）で対象を特定するようにしました。未定リストのモーダルから日付を入力して保存する経路は元々ID指定だったため、これで両方の経路が同じ確実な照合方法に統一されます。
- あわせて、正規化した顧客名が2件以上のレコードで一致する（＝重複の可能性がある）場合に、未定リスト・リスト表示の該当カードに注意アイコン（⚠）を表示するようにしました。ドラッグ&ドロップや未定リストからの入力はもちろん、スプレッドシートを直接編集して発生した重複も含めて検出できます。スプレッドシートへの直接編集そのものはアプリの制御が及ばないため、事前に防ぐことはできませんが、発生に気づけるようにしています。

**スプレッドシートに直接新規行を入力する際のID列について**: **空欄のままで構いません。** データ入力の基本フローが「まずスプレッドシートに直接入力 → それを未定リストから確定させていく」である前提に合わせて、`getRegistrationData`（画面がデータを読み込むたび）が実行するタイミングで、ID列が空欄の行・他の行とIDが重複している行（前の行をコピーして新しい行を作った場合など）を自動検知し、新しいユニークなIDを振ってシートへ書き戻す処理（`ensureUniqueIds_`）を追加しました。ドラッグ&ドロップ等はこのIDで対象データを特定しているため、これによりスプレッドシート直接入力が起点でも常に正しい行だけが更新されます。

### 10. 第三者レビューで見つかった不具合の修正
一通り実装した後、独立した観点でのコードレビューを行い、以下の不具合を修正しました。

- **車検証リンクが消えるおそれ（重大）**: `ensureUniqueIds_`・`autoLinkVehicleInspectionPDF`・`saveRecord` はいずれも、シートの一部のセルだけを書き換えてから行全体を `setValues()` で書き戻す作りでした。読み込みに `getValues()`（計算結果の文字列）だけを使っていたため、書き戻しの対象になった行に含まれる**他のセルの `=HYPERLINK(...)` 数式が、計算結果の文字列に置き換わって壊れてしまう**不具合がありました。例えば、ID列が空欄の行を1件直しただけで、同じシート内の別の行にある正常な車検証リンクが巻き添えで消える、といったことが起こり得ました。数式を保持したまま読み込む共通関数（`getSheetDataPreservingFormulas_`）を用意し、書き戻しを行う3箇所すべてをこれに差し替えました。
- **日付の集計がタイムゾーンによってずれる可能性**: ダッシュボードの「今月」判定が `new Date("2026-08-05")` のようにDateオブジェクトを介して年月を取り出していたため、ブラウザのタイムゾーンがJST（UTC+9）より西側（例: 米国など）だと日付が1日ずれて集計される可能性がありました。日付文字列から直接年月を取り出す形に変更し、タイムゾーンの影響を受けないようにしました。CSV出力のファイル名の日付も同様に修正しています。

### 11. 未定リストを拠点→担当者でグループ表示、操作ヒントの注釈を削除
- 未定リストは、これまで登録順のフラットな一覧でしたが、既定で「拠点 → 担当者」の2段階でグループ化して表示するようにしました（拠点は 岐阜/大垣/多治見/高山/AAA/デモカー/その他 の順、担当者はグループ内で登場順）。拠点・担当者は見出しに出るので、カード自体からは重複する表示（拠点バッジ・SALES表記）を外し、その分カードをコンパクトにしています。
- 「※カードをカレンダーへドラッグ＆ドロップ」「※カードをタップして登録日を確定」という操作ヒントの注釈は削除しました。

### 12. 未定リストを狭めてカレンダーを広げる
未定リストの列幅が画面幅の1/4（`lg:w-1/4`）で、広い画面では中身に対して余白が目立っていました。固定幅 `lg:w-[272px]` に変更し、カレンダー側は残り幅いっぱいに広がる `lg:flex-1` に変更しました（以前は3/4固定でした）。未定リストをOFFにした時の「カレンダー全幅」表示は変更していません。

### 13. UI全面リニューアル（縦スクロールカレンダー・コントロールパネル・マイページ・設定）
プレビュー(Artifact)での多数回のレビューを経て確定したデザインを、実際のアプリに反映しました。主な変更点は以下の通りです。

- **カレンダーを月グリッドから縦スクロールの日付リストに変更**。1日=1行で、登録内容は行内に横並びで表示します。行の高さは登録の有無に関わらず均一です。開いた瞬間に「今日」の行が一番上に来るよう自動スクロールします。
- **土日祝の色分け**：土曜＝青、日曜＝ピンク、祝日＝緑の背景で行全体を色分けします。祝日は固定日＋ハッピーマンデー＋春分/秋分の計算に加え、振替休日・国民の休日も自動判定します（過去の五輪特例年などの例外までは対応していません）。
- **登録カードは固定サイズ**（顧客名は文字数に関わらずカードサイズが変わりません）。1行目に顧客名(太字)＋登録方法、2行目に担当者＋モデルを表示します。
- **未定リストは右側のオーバーレイパネル**に変更（カレンダー幅を圧迫しません）。開閉可能・内部スクロール対応で、月切替ボタンと重ならないよう表示範囲をカレンダー一覧部分に限定しています。
- **集計ヘッダー**：総登録台数・OSS登録台数・OSS登録率のタイル＋拠点別タイルを表示。
- **左側にコントロールパネル**（ナビゲーション）を追加し、「カレンダー」「マイページ」「設定」を切り替えられるようにしました。上部中央のアイコンは設定ページから変更できます（権限者のみ）。
- **マイページ**を新設。ログイン中のGoogleアカウントと「マイページ連携設定」（後述）で紐づけたフルネームをもとに、自分が担当者になっている登録だけを表示します。月切替、月ごとのKPI（受注台数/登録済み/未定/OSS登録率）、顧客名・拠点・登録方法での絞り込み、車検証PDFの閲覧ボタンに対応しています。まだ紐づけされていないアカウントでは、その旨を案内する画面が表示されます。
- **設定ページ**を新設。
  - **テーマ設定**（全ユーザー利用可）：アクセントカラーを8色から選べます。選択は「保存」を押すまで確定しません。保存内容は`PropertiesService.getUserProperties()`でGoogleアカウントごとに保存され、そのアカウントでアクセスしたときだけ反映されます。
  - **サイドパネルアイコン設定**（権限者のみ）：左上に表示するアイコンを選べます。全ユーザー共通の設定として`PropertiesService.getScriptProperties()`に保存されます。
  - **マイページ連携設定**（権限者のみ）：Googleアカウントとフルネームの対応表を管理します。**編集権限（`EDITOR_EMAILS`）とは別の設定**で、ここに登録しても編集権限は付与されません。専用シート `settings_マイページ連携` に保存されます。担当者欄の入力とここに登録するフルネームの表記（全角/半角、旧姓、ニックネームなど）が一致しないと、そのユーザーのマイページには何も表示されないため、表記を揃えて運用してください。
- **リスト表示・CSV出力・検索/絞り込み**など、既存の機能はそのまま維持しています（登録編集モーダル・ドラッグ&ドロップは下記14.の変更で廃止しました）。
- **PC画面の高さにぴったり収まるレイアウト**に変更し、ページ全体はスクロールしません（カレンダー一覧・未定リスト・マイページ一覧など中身が多い箇所だけが内部スクロールします）。860px未満の画面幅では、この固定レイアウトを解除し通常のスクロールに切り替えます（縦スクロールカレンダー自体はそのまま使えますが、既存のスマホ専用タブ切り替えUIほど作り込んではいないため、実機での見え方は別途確認をおすすめします）。

### 14. アプリを閲覧専用に変更し、登録・編集はスプレッドシート直接編集に一本化
これまではアプリ画面からも登録の追加・編集・ドラッグ&ドロップでの日付確定ができましたが、運用をスプレッドシート中心に統一するため、アプリ側からの書き込みをすべて廃止しました。

- **アプリからの新規登録・編集・ドラッグ&ドロップを廃止**：カレンダーの「＋新規登録」ボタン、空の日付行の「登録を追加」、未定リストからカレンダーへのドラッグ&ドロップはすべて削除しました。カード・行をクリックすると開く画面も、全項目readonlyの「登録内容」詳細表示のみになります（保存ボタンはありません）。`Code.gs` の `saveRecord` 関数自体も削除しました。
- **スプレッドシートに直接入力する運用に変更**：`db_登録データ_YYYY_M月` シートを直接編集して登録します。新しい月のシートは、GASエディタの関数選択メニューから `createNextMonthSheet` を実行すると、見出し・入力しやすくするための注釈・プルダウンつきで自動作成されます（既存シートに同じ書式を当て直したいときは `refreshAllSheetTemplates` を実行してください）。
- **各列に入力ガイドの注釈(コメント)を追加**：ヘッダーセルにマウスを乗せると、その列に何を入力すればよいかの説明が出ます。「ステータス」「拠点」「OSS区分」はプルダウンで選択する入力規則も設定しています。
- **ステータスの選択肢を変更**：「登録日未定 / 登録日確定 / 書類準備中 / 書類完了 / 登録完了」の5択から、次の3択に変更しました。
  - 登録書類到着待
  - 登録書類到着済
  - 登録予定日確定（これだけがカレンダーに日付付きで表示され、それ以外は未定リストに表示されます）

  **⚠ 既存データの移行が必要です**：これまでのシートには旧ステータス名（「登録日確定」など）が入力済みのはずです。アプリ側は旧「登録日確定」も引き続き確定扱いとして読み替えるようにしているため、当面はカレンダー表示は壊れませんが、プルダウンの入力規則は新しい3択でしか通らないため、既存セルは「無効な値」として警告表示されます。落ち着いたタイミングで、既存の「登録日確定」を「登録予定日確定」に一括置換（Google スプレッドシートの「検索と置換」機能）することをおすすめします。「登録日未定」「書類準備中」「書類完了」「登録完了」は、いずれもアプリからは「未確定（未定リスト行き）」として扱われるため、実害はありませんが、こちらも新しい3択に整理していただくのが理想的です。
- **スプレッドシートのID列を廃止**：ID列はアプリからの編集・ドラッグ&ドロップの対象を特定するためだけに使っていましたが、その機能自体がなくなったため削除しました。新規シートには含まれません。既存シートに残っているID列は削除しても問題ありませんが、残したままでもアプリの動作に影響はありません（アプリは列名で読み込むため、余分な列は無視されます）。
- **同姓同名の重複チェックをアプリからスプレッドシートへ移動**：アプリ側の重複警告アイコンは廃止しました（同月に同名で2台登録される正当なケースがあるため、アプリ側ではエラー扱いしません）。代わりに、各シートの「顧客名」列に条件付き書式を設定し、同じシート内（＝同じ月）に完全に同じ名前が2件以上あるセルは薄いオレンジ色で自動的に強調表示されます。
- **サイドパネルアイコンをプリセットのアイコン選択から画像アップロード方式に変更**：設定ページからアイコン画像をアップロードできます。画像はGoogle Driveの指定フォルダに保存し、表示側はDriveのサムネイル配信を利用して常に一定サイズの円形アイコンとして表示するため、大きな画像をアップロードしても見た目のサイズは自動的に整います。**保存先のDriveフォルダIDは設定ページ（サイドパネルアイコン設定カード内）から入力・保存できます**。コードの編集は不要です（未設定のままアップロードするとエラーメッセージが表示されます）。
- **未定リスト(オーバーレイパネル)の横幅を縮小**：カレンダー側のカード幅(178px)にあわせて284px→216pxに縮め、開いているときもカレンダーがより広く見えるようにしました。
- **アイコン保存先のDriveフォルダIDを設定ページから指定可能に変更**：これまで`Code.gs`内の定数として直接コード編集が必要でしたが、`getSideIconFolderId`/`saveSideIconFolderId`を追加し、`PropertiesService`（スクリプトプロパティ）で保存するようにしました。設定ページの「サイドパネルアイコン設定」カードにフォルダID入力欄を追加し、権限者はコードを触らずに保存先を設定・変更できます。
- **カレンダー1日あたりの表示件数と余白を調整**：横方向の空きスペースを活かせるよう、1日に表示するカードの上限を3件→8件に拡大し、カードが折り返す際の隙間も詰めて、空白や無駄なスクロールを減らしました。

### 15. 新車・中古車の2本立て化、カレンダーの横スライド表示、お知らせ／カレンダー設定、担当者マスタの拡充

- **カレンダー9件目以降は横スライド表示に変更**：1日の登録件数が9件以上になる日は、これまでの「+N件」タップ→モーダル一覧ではなく、その日の行を左右にスライドして続きを見る方式に変更しました。日付列（左端）はスライドしても位置が固定されたままです。9件目以降がある日は、カード列の右端に丸いスライド案内アイコン（›）が表示され、タップまたは横スクロールで続きを確認できます。
- **お知らせ機能を追加**：設定ページに「お知らせ設定」カード（権限者のみ編集可）を追加しました。登録したお知らせは、画面最上部の全幅バナーに常時表示されます（閉じるボタンで非表示にできますが、次回アクセス時は再度表示されます）。保存は`PropertiesService.getScriptProperties()`に行われ、全ユーザー共通です。
- **カレンダー設定（日付ごとの案内）を追加**：設定ページに「カレンダー設定」カード（権限者のみ）を追加しました。車両区分・年・月を選んで、その月に表示する案内（書類提出締切日など）を日付ごとに最大10件まで登録できます。登録した案内はカレンダーの該当日の日付バッジ右上に小さなアイコンとして表示され、タップすると内容がモーダルで確認できます。
- **新車・中古車の2本立てカレンダーに対応**：左のコントロールパネルの「カレンダー」の下に「新車」「中古車」の切り替えが追加され、それぞれ独立したカレンダー・未定リスト・リスト表示・マイページ集計を確認できます。
  - スプレッドシートは車両区分ごとに完全に別のシート群です。新車は従来どおり `db_登録データ_YYYY_M月` / `db_登録データ_未定`、中古車は新たに `db_登録データ_中古_YYYY_M月` / `db_登録データ_中古_未定` を使用します（新車側の既存シート名・データはそのまま変更していません）。
  - 中古車カレンダーの「拠点別登録台数」タイルからは「デモカー」を除外しています（新車側は従来どおり表示されます）。
  - 車検証PDFの自動リンクも車両区分ごとに独立しています。設定ページに新設した「車検証ファイル設定」カード（権限者のみ）から、新車・中古車それぞれの車検証保管フォルダのDrive IDを、コードを編集せずに登録できます。指定したフォルダ配下は階層の深さに関わらず再帰的に探索し、「2026.09」「2026.9」のどちらの表記の年.月フォルダにも対応して、顧客名が一致するPDFを見つけます。
  - PDF自動リンクの定期実行トリガーの関数名が `autoLinkVehicleInspectionPDF` から `autoLinkVehicleInspectionPDFNewCar` / `autoLinkVehicleInspectionPDFUsedCar` に変わりました。旧トリガーが設定済みの場合はGASエディタの「トリガー」画面から削除し、`setupPdfLinkTrigger` を再実行して新しいトリガー（新車・中古車の2本）を設置し直してください。
  - `createNextMonthSheet()`（新車用）に加えて `createNextMonthSheetUsedCar()`（中古車用）を追加しました。`refreshAllSheetTemplates()` は新車・中古車どちらのシートにもまとめてテンプレートを当て直します。
- **マイページから拠点の絞り込みを削除**、代わりに**ステータス列を追加**：マイページの検索条件から「拠点」の選択を廃止しました（一覧の各行には引き続き拠点バッジが表示されます）。かわりに一覧に「ステータス」列を追加し、スプレッドシートに入力した値（登録書類到着待／登録書類到着済／登録予定日確定）がそのまま確認できます。あわせて、一覧の「車検証」欄の「未アップロード」表記が折り返さないよう幅と`white-space`を調整しました。
- **「マイページ連携設定」を「担当者マスタ」に改称し、拠点の紐づけと保存ボタンを追加**：設定ページのこのカードは「担当者マスタ」という名称になりました。氏名・Googleアカウントに加えて「拠点」も登録できます（登録データの拠点集計とは独立した、担当者マスタ上の管理用の拠点情報です）。アプリからの登録・削除はこれまで即時保存でしたが、テーマ設定などと同様に、変更内容をその場で確定させず「保存」ボタンを押すまでは未保存として扱うように変更しました。また、アプリから直接編集できる項目ではあるものの、権限者アカウント自身の扱いを明確にするため、一覧を「権限者ログインアカウント」と「そのほかのアカウント」の2グループに分けて表示するようにしました（`EDITOR_EMAILS`と照合して自動判定）。
- **スプレッドシート側で担当者マスタ未登録の警告表示を追加**：各シートの「担当者」列に条件付き書式を設定し、担当者マスタ（`settings_マイページ連携`シート）に登録されていない氏名が入力されたセルは薄い赤で強調表示されるようにしました（`applySheetGuidance_`内の`担当者`列チェックとして、既存の「顧客名」重複チェックと同様の仕組みで追加）。

## セットアップ

1. `npm i -g @google/clasp` → `clasp login`
2. このフォルダで `clasp create --type webapp --title "登録カレンダー"` （または既存プロジェクトに `clasp push`）
3. `Code.gs` の `EDITOR_EMAILS` に、設定ページの管理項目（サイドパネルアイコン設定・車検証ファイル設定・お知らせ設定・カレンダー設定・担当者マスタ）を操作できるGoogleアカウントを追加
4. デプロイ後、権限者アカウントでログインし、設定ページの「サイドパネルアイコン設定」カードからサイドパネルアイコン画像を保存するDriveフォルダのIDを入力・保存（コード編集は不要）
5. 同じく設定ページの「車検証ファイル設定」カードから、新車・中古車それぞれの車検証PDF保管フォルダのDrive IDを入力・保存（コード編集は不要）。フォルダ内は `2026.08` または `2026.8` のような年.月フォルダで分けて運用してください（サブフォルダは何階層でも自動探索されます）
6. GASエディタから `setupPdfLinkTrigger` を一度だけ手動実行し、新車・中古車それぞれのPDF自動リンクの定期実行トリガー（15分おき）を設置
7. 既存の `db_登録データ` シート（新車・中古車とも）がある場合は、GASエディタから `refreshAllSheetTemplates` を一度実行し、入力ガイドの注釈・プルダウン・重複/担当者マスタチェック書式を適用。中古車用シートを新規に始める場合は `createNextMonthSheetUsedCar` で最初の月のシートを作成
8. GASエディタの「デプロイ」→「ウェブアプリ」で、アクセスできるユーザーを組織内に限定してデプロイ

## 未対応・今後の検討事項

- `EDITOR_EMAILS` はコード内の配列管理のため、非エンジニアが追加/削除するにはコード編集＋再デプロイが必要です。将来的にはスプレッドシートの管理シートで管理者を管理する方式への変更も検討できます。
- お知らせバナーの「閉じる」は表示中のセッション（render()を呼び直すまで）のみ有効で、ページを再読み込みすると再度表示されます。恒久的に非表示にする機能は未実装です。
- カレンダー設定・担当者マスタの日付/氏名入力欄は、入力の妥当性（日付形式や重複行など）を厳密にはチェックしていません。誤った内容を保存すると「保存しました」の表示のまま反映されるため、保存後にカレンダー/マイページ側の見え方を確認することをおすすめします。
- 現状、閲覧そのもの（顧客データの読み取り）はデプロイのアクセス設定（ドメイン内）に委ねています。閲覧できる人の範囲も絞りたい場合は別途ご相談ください。
- 既存データのステータス値は新しい3択（登録書類到着待/登録書類到着済/登録予定日確定）へ手動での一括置換が必要です（上記14.参照）。
- 担当者マスタは「担当者」欄の文字列とフルネームの完全一致で紐づけます。表記ゆれがあると該当ユーザーのマイページに何も表示されず、エラーも出ません（スプレッドシート側では担当者マスタ未登録の警告表示で気づけます）。設定画面に「どの担当者名にも紐づいていない一覧」を出す等の改善は未実装です。
- 中古車カレンダーを新規に使い始める場合、`db_登録データ_中古_...` シートにデータが1件も無いうちはマイページ・未定リストとも空表示になります。運用開始前に `createNextMonthSheetUsedCar` 等でシートを用意してください。
- 同姓同名の重複チェックは完全一致のCOUNTIFによるスプレッドシート側の条件付き書式です。全角/半角や法人格表記のゆれ（例:「株式会社」と「(株)」）までは検出しません。
- 860px未満の画面幅ではレイアウトの作り込みを最小限に留めています（固定ビューポートを解除するのみ）。スマホでの利用頻度が高い場合は、実機確認のうえ追加調整をおすすめします。
