# 中古車 販売可能リスト（GAS実装）

中古車ディーラー向けの**車両在庫・Hold（仮確保）・受注確定管理**アプリです。
Google スプレッドシートをDBとし、GASの HTML Service でWebアプリ（カード形式の在庫掲示、
Hold（仮確保）、受注確定までを一元管理）を提供します。

本アプリは、新車向けに構築した `vehicle-order-app`（本リポジトリの別ディレクトリ）を
ベースに、中古車業務向けの管理項目・画面へ置き換えたものです。Hold（仮確保・72時間期限・
2nd Hold・管理者限定のデモカーHOLD／他店HOLD）、受注確定、監査ログ、通知、設定機能
（テーマ・担当者マスタ・モデル写真・演出バリエーション）、PWA対応などの基本構造は
`vehicle-order-app` を踏襲しています。新車特有の機能（発注リスト・Gクラス予約リスト、
MP・有償OP・VPC・入港予定日・可能月・在庫開示といった項目）は持たず、代わりに中古車の
個体管理に必要な項目（登録番号・型式・車台番号下４桁・走行距離・車検満了日・販売価格・
リサイクル料等）を管理します。

Hold中の車両にはカード上に72時間の残り時間を進捗バー付きでリアルタイム表示し（毎秒更新）、
Hold・受注確定・設定保存の各操作はボタンを処理中表示にして多重送信を防止、
サーバー応答が一定時間ない場合はタイムアウトしてエラー表示に戻るため、操作後に画面が
固まって見える状態を防いでいます。

在庫リストの検索（キーワード）は、モデル（アルファベットのみのキーワードは先頭の
アルファベット部分との完全一致）に加えて、コミッション・ＯＣＮ・車台番号下４桁・
登録番号にも部分一致します（`inventoryMatchesKeyword_`）。

Hold（予約）・受注確定の共通入力項目（`HOLD_ORDER_INPUT_COLUMNS`、すべて必須）:

| 項目 | 内容 |
|---|---|
| 販売拠点 / リード番号 / 登録月 / 顧客 | テキスト。販売拠点はHold登録時も含めて必須で、ログイン中の担当者が担当者マスタに登録している拠点名から自動的に入力されます（編集可） |
| 担当者 | 入力不要。ログイン中のGoogleアカウントから、担当者マスタ（メールアドレス）を突き合わせて自動的に設定されます |
| 下取車の有無 / 保険加入の有無 | あり・なし の選択式 |
| OSS登録の可否 | 可・不可 の選択式 |
| 支払方法 | 現金・ローン・リース の選択式 |

**入力は2ステップ**: Hold登録・2nd Hold登録・受注確定のモーダルは、項目を一度に
出さず「ステップ1: 顧客情報（販売拠点・リード番号・顧客・担当者表示）」→
「ステップ2: 契約条件（登録月・下取車・OSS・保険・支払方法）」の2画面に分けています。
ステップ1の必須項目が未入力のまま「次へ」を押すとエラーを表示して進めません。
担当者はログインアカウントから自動判定されるため、ステップ数が増えても入力の手間
自体は増えません。

- **在庫リスト**シート: `INVENTORY_COLUMNS`。車両情報＋Holdステータス（available/hold）のみを保持します。
- **Holdリスト**シート: `HOLD_COLUMNS`。1台の車両につき 1st Hold・2nd Hold それぞれ最大1行
  （`コミッション`＋`順番`で一意）。上記の入力項目一式に加え、**担当者メール**（`staffEmail`。
  ログイン中のGoogleアカウントとの本人確認に使う識別キー。「担当者」欄はあくまで表示名）・
  開始日時・期限・カレンダーイベントIDを保持します。車両情報とは別テーブルで管理し、
  一覧表示時に `commission` をキーに結合します（`attachHoldInfo_`）。
  - **2nd Holdの72時間は、1st Holdの72時間が終了した時点から起算**します（登録した瞬間からではありません）。
    1st Holdの期限が切れた時点で2nd Holdが存在すれば、Holdリストの当該行の「順番」を1stへ昇格させ、
    旧1st Hold行を削除します（`processExpiredHolds`）。
- **受注リスト**シート: `ORDER_COLUMNS`。受注確定時に在庫リストの行から車両情報を転記し、
  上記の入力項目一式（販売拠点・担当者メールを含む）・受注確定日時を追記します。在庫リストの
  該当行と、Holdリストの該当コミッションの行（1st/2ndとも）を削除します（二重管理防止）。
- **変更履歴**シート: `AUDIT_LOG_COLUMNS`。Hold登録・2nd Hold登録・Hold解除（手動・自動）・
  受注確定のたびに1行追記します（更新・削除はしません）。列は 日時／操作／コミッション／
  モデル／担当者／担当者メール／詳細。時間主導トリガーによる自動処理（Hold自動解放・
  Hold自動昇格）は担当者欄に「システム（自動処理）」と記録されます。アプリ側に専用の
  閲覧画面はなく、スプレッドシートを直接確認する運用です。
- 設定（テーマ・ロゴ・モデル写真・通知先メール・Google Chat通知先Webhook URL・担当者マスタ・
  Hold登録／2nd Hold登録／受注確定の演出バリエーション）はScript Properties
  （`PROP_KEYS`）に保存します。

## ログイン連携について（重要な前提条件）

Hold登録・2nd Hold登録・受注確定・Hold解除の「担当者」は、**ログイン中のGoogleアカウントの
メールアドレス**と、設定タブの担当者マスタを突き合わせて自動的に判定されます。担当者マスタに
登録されていないGoogleアカウントでは、これらの操作は行えません（エラーメッセージで案内されます）。

この判定を機能させるには、Webアプリのデプロイ設定で「実行するユーザー」を
**アプリにアクセスするユーザー**にする必要があります。「アクセスできるユーザー」は、
運用形態に応じて次のいずれかにしてください。

- **Google Workspace（組織のGoogleアカウント）で運用する場合**: 「組織内のユーザー」
  （同一ドメイン）または利用者を個別指定。
- **個人のGoogleアカウント（＠gmail.com等）で運用する場合**: 「**Googleアカウントを
  持つ全員**」（`appsscript.json` の `access` は `ANYONE`）。個人アカウントには
  「組織内」に相当する設定が存在しないため、これを選ぶ必要があります。

どちらの場合も、「実行するユーザー」が「自分」のまま、または「アクセスできるユーザー」が
**ログイン不要の「全員（匿名ユーザーを含む）」**（`access: ANYONE_ANONYMOUS`）になっていると、
ログイン自体が発生しないため `Session.getActiveUser().getEmail()` が常に空文字を返し、
担当者はもちろんログイン中のGoogleアカウント自体が画面に表示されません
（画面右上に「ログイン情報を取得できません」と表示されます）。

## 受注確定の権限

Hold中の車両は、そのHoldを行った担当者（1st Hold担当者）のみが受注確定できます
（`canConfirmOrder_`）。Holdが入っていない在庫あり車両は、誰でも受注確定できます。
本人確認は表示名ではなく、ログイン中のGoogleアカウントのメールアドレス（`staffEmail`）で
行います。

## Hold解除

Holdの解除（顧客都合等での取り下げ）は、そのHoldを登録した本人のみ可能です（`canCancelHold_`）。
1st Holdを解除した際に2nd Holdが存在すれば、2nd Holdを1stへ繰り上げます（そこから改めて
72時間を与え直します）。2nd Holdを解除した場合は、その行を削除するのみで1st Holdには
影響しません。

## 管理者限定のデモカーHOLD・他店HOLD

`Constants.gs` の `SYSTEM_ADMIN_EMAILS` に登録された管理者権限を持つ担当者のみ、通常のHoldに
加えて「デモカーHOLD」「他店HOLD」を登録できます。どちらもHold期限が無期限（`expiresAt`が
`null`）で、カレンダー連携もありません。デモカーHOLDはリード番号・登録月のみ（任意入力）、
他店HOLDは販売店のみ（任意入力）で登録でき、通常のHoldの入力項目（顧客・下取車の有無等）は
一切要求されません。

## Googleカレンダー連携

Hold登録・2nd Hold登録を行うと、登録者本人のGoogleカレンダーに期限リマインドのイベントが
自動作成されます（期限の3時間前に通知）。Hold解除・受注確定時には、本人が登録したイベントを
自動削除します。時間主導トリガーによる自動解放・自動昇格ではカレンダー操作は行いません
（実行者が担当者本人ではないため）。デモカーHOLD・他店HOLDは期限が無期限のため、そもそも
カレンダーイベントを作成しません。

## Hold期限切れ処理の信頼性

`processExpiredHolds()` は5分おきの時間主導トリガーで繰り返し実行される冪等な処理です。
失敗した場合は1回だけ即時リトライし、それでも失敗した場合は設定タブに登録した
「システムエラー通知先」へメールで通知します。

## 在庫データの整合性チェック

在庫の追加・編集はスプレッドシートへ直接行う運用のため、手作業ならではのミス（コミッションの
重複貼り付け、モデル名の記入漏れ、Holdステータス欄への想定外の値の入力等）が紛れ込む
可能性があります。アプリ起動時に自動チェックし、問題があれば画面上部にバナーで警告します
（`checkInventoryIntegrity_`）。操作をブロックすることはなく、あくまで警告です。

## システムマスタ（管理者限定）

`SYSTEM_ADMIN_EMAILS` に登録されたGoogleアカウントのみ、設定タブの「システムマスタ」
（ロゴ・ローディング画像・お知らせ・モデル写真・メール通知先・担当者マスタ・演出
バリエーション）を編集できます。ロゴ・モデル写真・お知らせ・演出バリエーション・
ローディング画像は全利用者の画面に表示される値のため、編集画面は管理者限定にしつつ
値自体は非管理者にもそのまま渡します（`redactSystemMasterSettings_`）。

## 担当者マスタ

拠点・名前・Googleアカウントのメールアドレスを最大30人まで登録できます。ログイン中の
Googleアカウントと突き合わせて、本人の担当者名・登録拠点を自動判定します（拠点名は
Hold登録・受注確定の「販売拠点」欄の初期値としても使われます）。

## メール通知設定・Google Chat通知設定

Hold登録・受注確定のタイミングで、設定タブに登録したメールアドレス（複数可）へ通知メールを
送信します。Google ChatのWebhook URLを登録すれば、同じ内容をGoogle Chatのスペースにも
通知します（どちらか一方だけの設定でも動作します）。

## ホーム画面

モデル写真（`{ model, photoUrl, gradePrefix, gradeMarker, bodyType }`）を設定タブから登録すると、
ホーム画面にその代表写真と在庫台数が表示されます。1台ごとに個別登録することも、
複数台をまとめて1枚の写真で管理することもできます。1台ごとに個別登録したい場合は、
`gradePrefix` を空欄のまま `model` に在庫リストのMODEL列の値（型番）そのものを入力して
ください（従来どおりMODEL列の値と `model` を完全一致で照合します）。

複数台をまとめたい場合は、中古車は同じ表示名の中にも型番違いの車両が混在しうる
（例:「Cクラス」の中に「C200」「C300」「C220d」等）ため、在庫リストの「MODEL」列の値
（型番）を自動判定する条件として `gradePrefix`（先頭の文字列）・`gradeMarker`
（含む文字列）を指定できます（`vehicle-order-app` のグレード自動判定と同じ仕組み。
`gradeRuleSpecificity_` / `matchesGradeRule_`、JavaScript.html参照。両方とも大文字
小文字は区別しません）。

- `gradePrefix` は型番の**先頭にあるアルファベット連続部分（クラス名）と完全一致**した
  場合のみヒットします（`leadingAlphaPrefix_`、JavaScript.html参照）。単純な前方一致では
  なくこの方式にしているのは、`gradePrefix`「C」を単純な前方一致で判定すると、文字として
  「C」で始まる「CLA18」まで誤って拾ってしまい、「C20」（Cクラス）と「CLA18」（CLAクラス）を
  区別できなくなるため（現場からの指摘）。「C」は型番先頭のクラス名がちょうど「C」である
  型番（C20・C43T等）にのみ一致し、クラス名が「CLA」である型番には一致しません。
- `gradeMarker` は、`gradePrefix` を除いた型番の残りの部分に**その文字列がどこかに
  含まれていれば**（位置は問わず）優先的にヒットします。例えば `gradePrefix`「C」+
  `gradeMarker`「T」は、「C18T」「C18TZ」「C63T」のように、途中・末尾どこにTがあっても
  まとめて拾えるため、同じ「Tが付くグレード」を1枚の写真にまとめられます（「D」で
  ディーゼル系だけをまとめる、といった使い方も可能です）。一方、「CLA18」（Tを含まない）と
  「CLA18T」（Tを含む）のように、片方がもう片方に文字を継ぎ足しただけの別車両として
  分けたい場合は、`gradeMarker`「T」を登録すれば、Tを含まない「CLA18」は受け皿
  （`gradeMarker`未設定）の側に、Tを含む「CLA18T」は`gradeMarker`「T」の側に、
  それぞれ自動的に振り分けられます。

複数の登録条件に一致しうる型番（例:「CLA18T」がgradePrefix「CLA」（gradeMarker無し・
受け皿）の行にも、gradePrefix「CLA」+gradeMarker「T」の行にも一致する場合）は、より
長く具体的に一致する条件の側だけが数える対象になり、重複カウントされません
（`gradeRuleSpecificity_`が算出する具体性スコアで判定）。写真をクリックすると、その
自動判定条件（または個別登録した場合はその型番）に一致する在庫だけに絞り込んだ
在庫リストへ遷移します。

各モデル写真には任意で `bodyType`（型）を設定できます。選択肢はSedan・SUV・
Station Wagon・Compact・Coupe・Cabriolet/Roadster・Mini Vanの7種類です
（`MODEL_BODY_TYPE_OPTIONS`、Constants.gs参照）。`bodyType` は在庫の自動判定には
使わず、現時点ではホーム画面の表示グループ分けにも未使用の分類用の項目です
（将来、型ごとのグループ表示・絞り込みに利用する想定）。

## 表示設定（テーマ）・ロゴ・起動時ローディング画像・お知らせ

`vehicle-order-app` と同じ機能です。11種類の配色プリセット＋ランダム（ログインのたび
変化）から選べる着せ替えテーマ、ロゴ画像、起動時ローディング画面の画像、ホーム画面の
お知らせ文言を、いずれも設定タブから登録できます。

## 在庫リストの表示・検索

カード表示・表（横列）表示を切り替えられます。表（横列）表示は素のHTML `<table>`で
「ステータス・車種・ＯＣＮ・ハンドル・カラー・走行距離・販売価格・
1ST HOLD・2ND HOLD・操作」の10列を横一列に並べ、PCビューでは横スクロールが
発生しないようにしています。それ以外の項目（区分・コミッション・登録番号・型式・
車台番号下４桁・車検満了日・オプション等）は、カード表示・行タップで開く詳細モーダルで
省略せず確認できます。最大3台まで選んでスペックを比較できる車両比較機能もあります。

## 受注リストの月別管理・検索

受注確定日時から自動算出した「登録月」でグループ表示できるほか、販売拠点・モデルごとの
グループ表示にも切り替えられます。自由検索はモデル・コミッション・顧客名・担当・拠点に
部分一致します。

## マイページ

ログイン中の担当者本人がHold中の車両・受注した車両だけを抜き出して表示します。担当者
マスタに未登録のGoogleアカウントの場合は、その旨を案内するメッセージのみ表示します。

## リード番号の入力形式・登録月の初期値・スマートフォンでの入力時の自動ズーム防止

`vehicle-order-app` と同じ仕様です。リード番号は「L-」＋数字で保存され、アプリからは
数字のみ入力すれば自動的に「L-」が付与されます。登録月は当月を初期値にします。
スマートフォンでの入力欄タップ時にブラウザが自動的にズームしてしまう問題を、フォント
サイズの調整で防止しています。

## Hold登録・2nd Hold登録・受注確定 完了時の演出

設定タブから、Hold登録・2nd Hold登録・受注確定それぞれの完了時に表示する演出
（絵柄のアクション、A〜D）を選べます（案内メッセージ自体は固定です）。

## PWA対応（ホーム画面への追加）

ウェブアプリのURL（`.../exec`）に直接アクセスした場合、ホーム画面への追加（PWAとしての
インストール）が可能です。オフラインキャッシュは行いません（在庫・Hold・受注データは
常に最新をスプレッドシートから取得する必要があるため）。

## スプレッドシートの自動セットアップ（SetupService）

任意の空のGoogleスプレッドシートに本プロジェクトをコンテナバインドした状態で、GASエディタから
`setupSpreadsheet_()` を一度実行するだけで、在庫リスト・Holdリスト・受注リスト・変更履歴の
4タブ・ヘッダー・入力規則（選択式の列のドロップダウン）・列見出しの説明メモ・ＯＣＮ／コミッション列の
書式（先頭0保持）・Hold期限チェックの時間主導トリガーまで一括で整えられます。既存のシートが
ある場合は作り直さず、そのまま利用します。

各タブの列は、Constants.gsの列定義（`INVENTORY_COLUMNS` / `HOLD_COLUMNS` / `ORDER_COLUMNS` /
`AUDIT_LOG_COLUMNS`）から自動生成されます（`getOrCreateSheet_`）。そのため、今後アプリ側に
列が追加された場合も、この自動セットアップのコード自体を変更する必要はありません。

コンテナバインドのスプレッドシートを開くと、メニュー「販売可能リスト」からも
「初期セットアップ（4タブを作成）」「入力規則・列見出しの説明メモを再設定」
「ＯＣＮ・コミッション列を書式なしテキストに再設定」「ステア列の「右/左」を「R/L」へ一括変換」を
実行できます（`onOpen`）。

## セットアップ手順

1. **スプレッドシートの準備**
   - 空のGoogleスプレッドシートを新規作成し、下記2でこのプロジェクトをコンテナバインドした
     あと、GASエディタから `setupSpreadsheet_()` を一度実行するだけで「在庫リスト」
     「Holdリスト」「受注リスト」「変更履歴」の4タブ・ヘッダー・入力規則・ＯＣＮ／コミッション列の
     書式・Hold期限チェックのトリガーまで自動で整います。既存データがある場合は、後から
     「在庫リスト」タブに貼り付けてください。
2. **システムマスタの管理者メールアドレスを設定**
   - `Constants.gs` の `SYSTEM_ADMIN_EMAILS` を、実際にシステムマスタ（ロゴ・モデル写真・
     メール通知設定・担当者）へアクセスさせたいGoogleアカウントのメールアドレスに
     書き換えてください（配列、複数人可）。ここは担当者マスタと異なりコード上でのみ
     変更でき、画面からは変更できません。
3. **claspでのデプロイ**
   ```bash
   npm i -g @google/clasp
   clasp login
   clasp create --type webapp --title "中古車 販売可能リスト" --rootDir used-vehicle-order-app
   cd used-vehicle-order-app && clasp push
   ```
4. **スプレッドシートの紐付け**
   - 上記1で用意したスプレッドシートの「拡張機能」→「Apps Script」からスクリプトエディタを開き、
     コンテナバインドのスクリプトとして本プロジェクトのファイル一式を配置します（コンテナバインド
     であれば `SheetService.gs` の `getSpreadsheet_()` はそのまま動作します）。
     スタンドアロン運用する場合は `getSpreadsheet_()` を対象スプレッドシートIDでの `openById`
     に変更してください。
5. **トリガー設定**
   - 上記1で `setupSpreadsheet_()` を実行済みであれば、トリガーはその時点で設定済みです。
6. **Webアプリとして公開**
   - `clasp deploy` または GASエディタの「デプロイ」→「ウェブアプリ」。
   - **重要**: 担当者のログイン連携（「ログイン連携について」の項を参照）を使うには、
     デプロイ設定で「実行するユーザー」を **アプリにアクセスするユーザー** にしてください。
     「アクセスできるユーザー」は、個人のGoogleアカウント（＠gmail.com等）で運用するなら
     **「Googleアカウントを持つ全員」**、Google Workspaceで運用するなら「組織内のユーザー」
     （または利用者を個別指定）にしてください。「自分」のまま、または
     「全員（匿名ユーザーを含む）」のままだと担当者もログインアカウントも正しく判定されません。
7. **設定画面での初期設定**
   - 上記2で`SYSTEM_ADMIN_EMAILS`に登録したメールアドレスでログインし、Webアプリの
     「設定」タブ→「システムマスタ」から、ロゴ・モデル写真（ホーム画面）を必要に応じて
     登録し、Hold登録時／受注確定時／システムエラー時のメール通知先を登録してください
     （通知先未設定の場合、メール通知はスキップされます）。
   - 同じく「システムマスタ」の担当者（最大30人）に、各担当者の**拠点・名前・
     Googleアカウントのメールアドレス**を登録してください。ここに登録されていない
     メールアドレスでログインした人は、Hold登録・受注確定・Hold解除ができません。
   - テーマ（配色プリセット）は「テーマ」グループから、管理者以外の利用者でも変更できます。
