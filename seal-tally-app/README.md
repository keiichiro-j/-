# 封印集計システム（seal-tally-app）

自動車検査証記録事項のPDFから登録日と登録番号を自動で取り込み、封印の **明細書・台数集計書・報告書** を毎月自動で作る
Google Apps Script（V8）アプリ。管理用スプレッドシートにバインドして動かし、clasp でローカル管理する。

- 画面：GAS Webアプリ（`html/`、6タブ）。画面とサーバーの約束は `docs/API.md`
- データ：管理用スプレッドシート（明細・受入調整・対象外ログ・処理済ファイル・締め・地域名マスタ・設定・履歴・利用者）
- 帳票：書類ごとに1ファイル（年ごと）、月ごとにシート。管理データから毎回作り直す

## セットアップ手順

1. **管理用スプレッドシートを作る**（共有ドライブまたは管理者のマイドライブ。利用者4名だけに共有）。
2. **Apps Script プロジェクトを用意して clasp push する**
   - スプレッドシートの「拡張機能 > Apps Script」を開き、プロジェクトの設定からスクリプトIDを控える。
   - このディレクトリに `.clasp.json` を作る（git には入れない）：
     ```json
     { "scriptId": "<スクリプトID>", "rootDir": "." }
     ```
     （リポジトリのルートから使う場合は `"rootDir": "seal-tally-app"` とし、`.clasp.json` をルートに置く）
   - `npx @google/clasp login` → `npx @google/clasp push`（`.claspignore` で test/docs/README などは送らない）
3. **Drive API サービスを追加**：エディタの「サービス」から Drive API（v3、識別子 `Drive`）を追加
   （`appsscript.json` に記載済みなので、push 後に有効になっていることを確認するだけでよい）。
4. **`setup` を実行**：エディタで `setup` を選んで実行（またはスプレッドシートを開き直してメニュー「封印集計システム > 初期セットアップ」）。
   権限の承認後、次が行われる（何度実行してもよい）。
   - 全シートを見出し付きで作成（データ列は文字列書式）、地域名マスタ・設定の初期値
   - 利用者シートに実行者を **管理者** で登録
   - アプリ用フォルダ（未設定ならスプレッドシートと同じフォルダに「封印集計」）と、その下に 処理済／要確認／対象外／エラー／提出用
   - シート保護（所有者＝スクリプト実行者以外は編集不可）
   - トリガー：`runImport`（設定の間隔）、`runCloseReminder`（毎月1日 9時）
5. **ウェブアプリとしてデプロイ**：「デプロイ > 新しいデプロイ > ウェブアプリ」、実行ユーザー＝**自分**、アクセス＝**組織内**。
6. **アプリの設定画面で入力**
   - 4つの読み取りフォルダのURL（「確認」でフォルダ名と未処理件数が出ることを確認してから保存）
   - 開始月（初期値 2026-10）の月初の繰越数（ブランドA岐阜・ブランドB岐阜・ブランドA愛知）
   - 利用者と権限（4名。管理者1名・編集者3名）
7. **app.url を設定**：設定シートの `app.url` にWebアプリのURLを入れる（通知メールに記載される）。
8. 「封印集計」フォルダを利用者4名に**閲覧者**で共有する（帳票ファイルはこの中に自動作成される）。

> **setup・ウェブアプリのデプロイ・トリガーの設定は、すべて同じ管理者アカウントで行うこと。**
> Webアプリは「実行ユーザー＝自分」で動き、トリガーは作った人の権限で動くため、別の人が行うと権限やトリガーが分かれてしまう。
> 2回目以降の setup とメニューの操作（今すぐ取込・帳票の作り直し・トリガーの再設定）は管理者のみ実行できる。
> 帳票ファイル・移動先フォルダはスクリプト実行者（管理者）の権限で作られる。読み取りフォルダは管理者がアクセスできる必要がある
> （共有ドライブにも対応）。

## 運用

- **毎日**：PDFを4つのフォルダに保存するだけ。自動取込（初期値10分ごと）で明細に登録され、PDFは
  処理済/yyyy-MM・要確認・対象外・エラー のフォルダへ移る。要確認タブの件数を見て、PDFと並べて確認・修正する。
- **受入・調整**：封印を受け取ったとき、破損・返納で減ったときだけ「受入・調整」タブで登録。取消は行を残して無効にする。
- **毎月1日（締め）**：9時にリマインドメール。管理者が帳票タブで前月を「締める」。
  重複・要確認・誤りの疑いが残っていると締められない（件数が表示される）。締めると前月の明細・受入調整は変更できなくなり、
  月末残数が翌月の繰越として確定する。締め解除は管理者のみ・理由必須（履歴に残る）。
- **提出**：帳票タブの「提出用に出力」で、当月の帳票シートを1シート1PDFで「提出用/yyyy-MM」に保存する。
- **通知**：残数が `notify.lowStock`（初期値10）を下回った時点で1回だけ（回復後に再び下回れば再送）。
  取込エラーは管理者へ。通知先は `notify.to`（空なら利用者全員）。
- **締めの順番**：締められるのは前月以前の月だけで、前の月から順に締める（前月が未締めなら締められない）。
  締め解除は新しい月から順に行う（後の月が締め済みなら解除できない）。登録日が決まっていない要確認の明細のうち、
  登録日候補にその月が含まれるもの（候補がなければ取込日時がその月か翌月のもの）も締めを妨げる。
- **締め済みの月のPDFが後から届いた場合**：「締め済みの月の明細です」というチェック付きの要確認として登録し、
  PDFは「要確認」フォルダへ移して管理者にメールする。その月の既存の明細と帳票は締めたときのまま。
  締め解除すると、その明細もふつうの判定に戻る。
- **帳票の作り直し**：前の月の明細や受入を変えると繰越が変わるため、その月から今月までの未締めの月の帳票を作り直す。
  取込で時間が足りないときは帳票の作り直しを次回の取込に回す（スクリプトプロパティ `pendingReportMonths`）。
- **出力ファイルのID**：設定の `output.fileId.*` は `{"2026":"年ごとのID","all":"1ファイルのときのID"}` の JSON。
  output.yearly を切り替えても元のファイルを使い続ける。

## テスト

```sh
cd seal-tally-app
npm test        # = node test/run.js
```

抽出・判定・残数（`test/run.js`）と帳票の組み立て（`test/reports.test.js`）を、GAS なしの Node.js で確認する。
GAS 上の動作確認（フェーズ1）は、実物のPDFで `debugExtract('<ファイルID>')`（本文と抽出結果をログに出す）や
`debugExtractAll(20)`（4フォルダのPDFの抽出結果を一覧でログに出す。本文は出さない）を実行する。
どちらも明細への登録・ファイル移動はしない。`debugExtract` のログには所有者名・住所が含まれるので共有しないこと。

## 未確定事項

### 帳票の正式レイアウト（テンプレート差し込み）

正式レイアウトが届くまでは標準レイアウトで出力する。届いたら次のようにする（コードの変更は不要）。

1. 管理用スプレッドシートに、レイアウトを描いたシートを **「テンプレート_明細書」「テンプレート_台数集計書」「テンプレート_報告書」**
   という名前で追加する（非表示でよい）。年ごとの帳票ファイルにも自動で複製されるので、年が変わっても登録し直さなくてよい。
   特定のファイルだけレイアウトを変えたいときは、その帳票ファイルに **「テンプレート」** シートを置けばそちらが優先される。
2. 設定シートの `layout.detail` / `layout.count` / `layout.report` に差し込み位置を JSON で入れる。
3. 次に帳票を作り直すと、月のシートは「テンプレート」の複製に値を差し込んだものになる。

列は `"D"` のような英字でも `4` のような数字でもよい。使わない項目は省略できる。

```json
// layout.detail（明細書）
{ "monthCell": "B2", "titleCell": "E2", "startRow": 5, "dateCol": "A", "dowCol": "B", "countCol": "C",
  "plateCol": "D", "maxPerRow": 10, "totalCell": "C36" }

// layout.count（台数集計書）
{ "monthCell": "B2", "titleCell": "E2", "carryCell": "F4", "startRow": 5, "dateCol": "A", "dowCol": "B",
  "receivedCol": "C", "adjustedCol": "D", "usedCol": "E", "balanceCol": "F", "totalRow": 36 }

// layout.report（報告書）
{ "monthCell": "C3", "unitCell": "C4", "carryCell": "C6", "receivedCell": "C7", "adjustedCell": "C8",
  "usedCell": "C9", "leftCell": "C10" }
```

- 日付は1日〜月末を `startRow` から下へ月の日数分書く。日付・曜日・登録番号・年月などの文字のセルは、
  書く前に文字列書式にする（「10/19」が日付に変換されないように）。
- 1行に入りきらない登録番号（`maxPerRow` 超え）は暫定で最後のセルを「ほかn件」にしている。
  次の行へ送るか別紙にするかはレイアウト受領時に決めて実装する。
- 調整は帳票上マイナスで表示する。

### そのほか

- 記録事項PDFの見本（個人情報を伏せたもの）による抽出ルールの最終確認（フェーズ1）
- 2026年10月1日時点の封印の残数 → 設定画面の「開始月の繰越数」に入力
- 4名のアカウントと管理者 → 設定画面の「利用者と権限」に入力
- 祝日は Googleカレンダー「日本の祝日」の説明欄が「祝日」のものだけを使う（節分などの行事は除く）。
  カレンダーの仕様が変わった場合は `Repo.gs` の `fetchHolidaysOfMonth_` を見直す。
