# 車両受注アプリ（GAS実装）

`b787266f-vehicleorderappproposal.docx`（車両受注アプリ 企画書）をベースにコード化した
Google Apps Script プロジェクトです。既存の車両在庫管理アプリ（本リポジトリのルート）・
新車売上在庫管理システムとは独立したシステムとして構築しています（企画書 1.・9.）。

Google スプレッドシートをDBとし、GASの HTML Service でWebアプリ（カード形式の在庫掲示、
Hold（仮確保）、受注確定までを一元管理）を提供します。

## データ構造

- **在庫**シート: `INVENTORY_COLUMNS`（`Constants.gs`）。コミッション（車両特定番号）をキーに、
  1st Hold・2nd Hold の担当者／顧客／各種可否・登録日時・期限を列として保持します。
- **受注リスト**シート: `ORDER_COLUMNS`。受注確定時に在庫シートの行から車両情報＋顧客情報を
  転記し、在庫シートの該当行は削除します（3.3、二重管理防止）。
- 設定（テーマ・通知先メール）は Script Properties（`PROP_KEYS`）に保存します。

## セットアップ手順

1. **スプレッドシートの準備**
   - 新規スプレッドシートを1つ作成します（初回アクセス時に「在庫」「受注リスト」タブが
     自動生成されます）。
2. **claspでのデプロイ**
   ```bash
   npm i -g @google/clasp
   clasp login
   clasp create --type webapp --title "車両受注アプリ" --rootDir vehicle-order-app
   cd vehicle-order-app && clasp push
   ```
3. **スプレッドシートの紐付け**
   - 作成したスクリプトをコンテナバインド（スプレッドシートの拡張機能からGASエディタを開く）
     するか、`Code.gs` 側でスタンドアロン運用する場合は `SheetService.gs` の
     `getSpreadsheet_()` を対象スプレッドシートIDでの `openById` に変更してください。
4. **トリガー設定**
   - GASエディタから `setupTimeDrivenTriggers_()` を一度だけ手動実行します
     （Hold期限チェック・5分毎）。
5. **Webアプリとして公開**
   - `clasp deploy` または GASエディタの「デプロイ」→「ウェブアプリ」。
6. **設定画面での初期設定**
   - Webアプリの「設定」タブから、テーマ配色とHold登録時／受注確定時のメール通知先を
     登録してください（未設定の場合、メール通知はスキップされます）。

## テスト

外部サービス（Spreadsheet/Mail等）に依存しない純粋ロジック（Hold・2nd Hold登録可否判定、
72時間経過時の昇格／解放処理、検索・グループ化）を Node.js の `vm` サンドボックスで検証します。

## 未実装・今回スコープ外

- **5. データ基盤**: 企画書では「既存の新車売上在庫スプレッドシートをそのままマスタデータ
  として使用する」とされていますが、当該スプレッドシートは本リポジトリ外にあり、実体・
  シート構成が未確認のため、本実装では在庫シートを本アプリ独自のマスタとして扱っています。
  実際の連携時は、既存シートの構成（シート名・列構成）の初期調査のうえ、
  `SheetService.gs` の在庫データ取得部分を既存シートの参照に置き換えてください。
- **在庫データの新規登録**: 上記の通り本来はスコープ外の機能ですが、独立システムとして
  最低限動作確認できるよう、Webアプリの在庫一覧タブから簡易的な「在庫追加」フォーム
  （`api_createInventoryVehicle`）のみ用意しています。
- **7. 開発体制・スケジュール・概算コスト**: 企画書のとおり今後確定次第、別途更新。
- Hold・2nd Holdの手動キャンセル（顧客都合等での取り下げ）は企画書に明記がないため未実装です。
  現状は72時間経過による自動解放／自動昇格のみでHold状態が変化します。
- 権限設計の詳細（編集者／閲覧者範囲、シート保護、承認フロー）。
