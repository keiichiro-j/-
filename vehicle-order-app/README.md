# 車両受注アプリ（GAS実装）

`b787266f-vehicleorderappproposal.docx`（車両受注アプリ 企画書）をベースにコード化した
Google Apps Script プロジェクトです。既存の車両在庫管理アプリ（本リポジトリのルート）・
新車売上在庫管理システムとは独立したシステムとして構築しています。

Google スプレッドシートをDBとし、GASの HTML Service でWebアプリ（カード形式の在庫掲示、
Hold（仮確保）、受注確定までを一元管理）を提供します。

## ファイル構成

| ファイル | 内容 |
|---|---|
| `Constants.gs` | 販売リスト・受注リストの列定義、選択肢 |
| `SheetService.gs` | 販売リスト・受注リストのCRUD基盤 |
| `HoldService.gs` | Hold（商談確保）機能、72時間経過時の2nd Hold昇格処理 |
| `OrderService.gs` | 受注機能（販売リスト→受注リストへの自動移行） |
| `SearchService.gs` | 検索・グループ表示 |
| `NotificationService.gs` | メール通知機能 |
| `SettingsService.gs` | 設定機能（テーマ、通知先） |
| `Api.gs` | クライアント（HTML）から呼び出すユースケース単位API |
| `Triggers.gs` | Hold期限チェックの時間主導型トリガー |
| `Code.gs` | `doGet` エントリポイント |
| `html/Index.html` `html/Stylesheet.html` `html/JavaScript.html` | Webアプリ画面（販売リスト／受注リスト／設定、カード型・Material Designベース） |
| `tests/run.js` | 外部サービス非依存の純粋関数（Hold可否判定・期限処理・検索・グループ化）の単体テスト |

## データ構造

車両情報の列（`VEHICLE_COLUMNS`、販売リスト・受注リスト共通）:

| 列 | 内容 |
|---|---|
| 車種 / モデル / MP / ステア / 外装 / 内装 | 基本情報（ステアは 右・左 の選択式） |
| 有償オプション1〜5 | 有償オプションを5マス分確保 |
| コミッション | 車両ごとの一意なキー |
| 入港予定日 | 日付 |
| VPC | テキスト |
| 在庫開示 | 開示・非開示 の選択式 |

Hold（予約）・受注確定の共通入力項目（`HOLD_ORDER_INPUT_COLUMNS`）:

| 項目 | 内容 |
|---|---|
| 登録月 | テキスト |
| 担当者 / 顧客 | テキスト |
| 下取車の有無 / 保険加入の有無 | あり・なし の選択式 |
| OSS登録の可否 | 可・不可 の選択式 |

- **販売リスト**シート: `INVENTORY_COLUMNS`（`Constants.gs`）。上記の車両情報に加え、
  1st Hold・2nd Hold それぞれについて上記の入力項目一式・登録日時・期限を列として保持します
  （アプリが自動管理）。
- **受注リスト**シート: `ORDER_COLUMNS`。受注確定時に販売リストの行から車両情報を転記し、
  販売拠点・上記の入力項目一式・受注確定日時を追記します。販売リストの該当行は削除します
  （二重管理防止）。
- 設定（テーマ・通知先メール）は Script Properties（`PROP_KEYS`）に保存します。

## 元データスプレッドシート

`vehicle-order-app-master-data.xlsx`（チャットで送付済み）に、上記の列構成に合わせた
「販売リスト」「受注リスト」「使い方」の3タブを用意しています。既存データはこのファイルの
「販売リスト」タブ・薄い青色のヘッダー列（車種〜在庫開示）へ貼り付けてください。薄いグレー
のヘッダー列（Holdステータス以降）はアプリが自動的に読み書きするための列なので、空欄のまま
にしておきます。「受注リスト」タブは受注確定時にアプリが自動で追記するため、手入力は不要です。

## セットアップ手順

1. **スプレッドシートの準備**
   - `vehicle-order-app-master-data.xlsx` をGoogleドライブにアップロードし、Googleスプレッド
     シートとして開きます（アップロード時に自動変換されない場合は「アプリで開く」→
     「Googleスプレッドシート」）。既存データは「販売リスト」タブに貼り付けてください。
   - すでにお手元のスプレッドシートに既存データがある場合は、このファイルをテンプレートとして
     列構成・ヘッダーだけ合わせても構いません。
2. **claspでのデプロイ**
   ```bash
   npm i -g @google/clasp
   clasp login
   clasp create --type webapp --title "車両受注アプリ" --rootDir vehicle-order-app
   cd vehicle-order-app && clasp push
   ```
3. **スプレッドシートの紐付け**
   - 上記1で用意したスプレッドシートの「拡張機能」→「Apps Script」からスクリプトエディタを開き、
     コンテナバインドのスクリプトとして本プロジェクトのファイル一式を配置します（コンテナバインド
     であれば `SheetService.gs` の `getSpreadsheet_()` はそのまま動作します）。
     スタンドアロン運用する場合は `getSpreadsheet_()` を対象スプレッドシートIDでの `openById`
     に変更してください。
4. **トリガー設定**
   - GASエディタから `setupTimeDrivenTriggers_()` を一度だけ手動実行します
     （Hold期限チェック・5分毎）。
5. **Webアプリとして公開**
   - `clasp deploy` または GASエディタの「デプロイ」→「ウェブアプリ」。
6. **設定画面での初期設定**
   - Webアプリの「設定」タブから、テーマ配色とHold登録時／受注確定時のメール通知先を
     登録してください（未設定の場合、メール通知はスキップされます）。

## テスト

外部サービス（Spreadsheet/Mail等）に依存しない純粋ロジック（Hold・2nd Hold登録可否判定、
72時間経過時の昇格／解放処理、検索・グループ化）を Node.js の `vm` サンドボックスで検証します。

```bash
npm test
```
