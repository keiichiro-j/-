# YANASE 中古車管理表 整備・読み取り改善（フェーズ1）

企画書「YANASE 中古車管理表 整備・読み取り改善 企画書（改訂版）」をコード化した Google Apps Script です。
AU・C7・MB の3社のスプレッドシートそれぞれに同じコードを入れ（コンテナバインド）、セットアップ画面で会社ごとに設定します。

入力の中心はスプレッドシートへの直接入力です。直接入力も自動読み取りも同じ自動整形を通るので、書式（半角カナ・西暦・数値）がそろいます。
自動読み取り（Gemini）は補助機能で、呼び出しは「1ファイル＝1回」まで、1日の上限つきです。

## ファイル構成（企画書 第8章）

| ファイル | 役割 |
|---|---|
| `Code.gs` | メニュー、セットアップ、自動整形（onEdit）、入力チェック、販売済み移動、自動読み取り、車検証リンク、一括整形、ログ |
| `Setup.html` | 初期セットアップ画面（会社名、フォルダ、APIキー、1日の処理上限、トリガー） |
| `Lists.html` | プルダウン選択肢の編集画面（メーカー・色・担当者・本人確認方法・地域名） |
| `Cleanup.html` | 一括整形・列統一のドライラン結果の確認と実行 |
| `appsscript.json` | マニフェスト（タイムゾーン・権限） |
| `tests/run.js` | 整形・チェック・読み取り組立など純粋ロジックの単体テスト（Node.js、追加依存なし） |

## 導入手順（企画書 第10章）

1. **事前準備**：Gemini APIキーを再発行する（旧コードに直書きされていたキーは無効化）。3社のスプレッドシートのバックアップを取る
2. **コードを入れる**（各社のスプレッドシートで）
   - 「拡張機能」→「Apps Script」を開き、`Code.gs`・`Setup.html`・`Lists.html`・`Cleanup.html` を同名で作成して貼り付ける
   - 以前の版の `Import.html`・`Review.html` が残っていれば削除する
   - プロジェクトの設定で「appsscript.json をエディタで表示」をオンにし、`appsscript.json` を置き換える
3. **セットアップ**：スプレッドシートを開き直し、メニュー「★専用システム」→「初期セットアップ／設定変更」を実行（初回は権限の承認が必要）
4. **選択肢の確定**：「プルダウン選択肢の編集」で担当者などを入力（初期値は案）。他社へは同じ画面の「書き出す／貼り付け」で同じ内容を反映
5. **既存データの整備**：メニュー「既存データの一括整形・販売済みシートの列統一」→ ドライランで確認 → 列統一 → 一括整形
6. **試用**：直接入力（自動整形・プルダウン・入力チェック）→ 自動読み取り（査定書から）

## セットアップで行うこと

- シート：輸入車マスタ、国産車マスタ、販売済み（同一列構成）、設定、ログ。既存シートは上書きせず、足りない列だけを右端に追加
- 見出し行、プルダウン（設定シートの選択肢を参照）、日付のカレンダー入力、表示形式（`yyyy/MM/dd`・`#,##0`・`12,345km`）
- 入力チェックの色分け（条件付き書式）と、見出し行・OCN列の保護（警告表示）
- 計算式の列：見出し行に ARRAYFORMULA を1つ置く方式（既存の式・値がある列は切り替えない）
- ドライブのフォルダ：受付、処理済み、エラー、車検証保管
- APIキーはスクリプトプロパティに保存（コードに書かない）
- トリガー：入力時の自動整形（編集トリガー）、自動読み取り・車検証リンクの定期実行

## 自動整形と入力チェック（企画書 第5章）

**入力時の自動整形**（Gemini は使わない。複数セルの貼り付けにも対応）
- 全角カナ→半角カナ、全角英数→半角英数、前後の空白を削除（登録番号のひらがなは全角ひらがなへ、漢字はそのまま）
- 和暦（R5.6.1、令和5年6月1日など）→ 西暦の日付
- 車台番号は大文字化、ハイフンは残す
- 走行距離・金額の「km」「円」「,」を外して数値化
- プルダウンの列は表記ゆれを選択肢へ変換（例：「メルセデス・ベンツ」→ MB、「ダークブルー」→ 紺）。変換の手がかりは設定シートの「別名」
- 自動読み取りで入ったセル（水色・黄色＋メモ）を人が直すと、色とメモを外す

**入力チェック（色で知らせる）**
- 赤：車台番号の重複（3シート横断）、登録番号4項目の組み合わせの重複
- 橙：車台番号・分類番号・一連番号の形式違い、初度登録日が未来、車検満了日が初度登録日以前
- 薄紫（行全体）：車検満了日が近い車両（日数はセットアップで設定）

**ステータス連動**
- ステータスを「販売済み」にすると確認のうえ販売済みシートへ移動（見出し名で列を対応づけるので列ずれなし）。確認画面を出せない場合はメニュー「ステータスが販売済みの行を販売済みシートへ移動」から
- OCN は車台番号・車種・モデル名のどれかが入った行に、会社単位（輸入車・国産車共通）の連番で自動採番

## 自動読み取り（企画書 第6章）

- 受付フォルダの書類を、定期実行またはメニュー「受付フォルダの書類を今すぐ読み取り」で処理
- **1ファイル＝Gemini 1回**（再読み取り・2重チェックはしない）。**1日の処理上限**を超えた分は翌日に回す
- 回数制限（429）や一時エラー（5xx）のときは、書類を受付フォルダに残して次回に再処理
- 対象は活字の書類：査定書（常に）、車検証（設定で有効にした場合）。注文書は対象外（エラーフォルダへ移し、直接入力）
- 読み取り結果にも自動整形をかけ、車台番号は文字補正（17桁の I・O・Q→数字、国産車の連番は数字のみ）
- 車台番号（無ければ登録番号）が既存行と一致したら、新しい行は作らず**空欄の項目だけを埋める**。入力済みと違う値はメモで知らせ、入力済みの値を残す
- 一致しなければ新しい行を追加（OCN採番、仕入年月日＝当日、ステータス＝書類待ち）
- 自動で入れたセルは水色＋メモ、疑わしい値・読めなかった項目は黄色＋メモ
- 車検証は `OCN.pdf` に改名して車検証保管フォルダへ移し、「車検証ﾘﾝｸ」を付与。査定書は `OCN_元の名前` で処理済みへ
- 処理件数・エラー・受付フォルダの残り件数・本日の読み取り回数をログシートに記録

**車検証リンク**：車検証保管フォルダでファイル名がOCNで始まるもの（`12345.pdf` など）を行と突き合わせてリンクを付けます（Gemini は使いません）。定期実行とメニューから。

## 既存データの一括整形と列統一（企画書 第7章）

メニュー「既存データの一括整形・販売済みシートの列統一」。まず**ドライラン**で変更予定を確認してから実行します。実行前に対象シートのバックアップ（`シート名_BK_日時` の非表示シート）を自動で作ります。

1. 販売済みシートの列統一：現行の列配置 → A〜AC（標準にない列はAD列以降に残す）
2. 書式の一括整形：自動整形と同じ規則で全セルを整える
3. プルダウン外の値の洗い出し：値ごとに置き換え先（候補を自動選択）／そのまま／選択肢に追加を選ぶ
4. 計算式の保護：計算式の列（車検残・下取損・仕入価格）と式の入ったセルは対象外
5. 結果レポート：変更したセル数・修正できなかったセルをログシートに記録

## 未確定事項（企画書 第11章）とコード上の変更箇所

| 確認事項 | 変更箇所 |
|---|---|
| 現行「販売済み」シートの見出し行 | 一括整形画面の列統一の対応表で確認。別表記は `FIELDS` の `aliases` に追加 |
| 計算式の列と式の内容 | `FORMULA_DEFS`（車検残・下取損は暫定式。仕入価格は未定義のため設定しない。既存の式はそのまま使う） |
| 「買取金額」が仕入価格（AC列）と同じ項目か | 同じ前提で AC列の見出しを「仕入価格（買取金額）」にしています |
| プルダウンの選択肢・メーカー表記ルール | 設定シート（「プルダウン選択肢の編集」画面）。初期値は `DEFAULT_LISTS` |
| 車検証の自動読み取りを有効にするか | セットアップ画面の「車検証も読み取る」 |
| 自社名義変更後の車検証リンク用の列（AD列） | 未対応。追加する場合は `FIELDS` に列を足し、`updateCertLinks_` で `OCN_自社名義` のファイルを対応づける |
| Gemini APIキーの再発行 | セットアップ画面で入力 |

## テスト

```bash
npm test
```

スプレッドシート・ドライブ・Gemini に依存しない純粋関数（半角カナ・和暦・金額の整形、プルダウンの表記ゆれ変換、
車台番号の補正、条件付き書式の数式、OCN採番、読み取り結果の組立、空欄だけを埋める計画、429の判定）を Node.js の `vm` で検証します。
シートやドライブを操作する部分は、1社での試験導入で実データにより確認してください。
