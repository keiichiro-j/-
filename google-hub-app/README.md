# Google連携統合管理アプリ（GAS実装）

`ab1f91ff-google_______________v2.docx`（Google連携統合管理アプリ 企画書 v2）をベースにコード化した
Google Apps Script プロジェクトです。Drive・Calendar・Mail と自社製GASアプリ群を1画面に集約する
「統合ホーム画面」を提供します。

他のプロジェクト（`vehicle-order-app/` 等）と異なり、本プロジェクトは企画書 13章の指定に従い
**clasp + TypeScript** でローカル開発し、ビルド成果物（`dist/`）をGASへpushする構成です。

## ディレクトリ構成

ファイル数を抑えるため、関連するnamespace・画面パーツはできるだけ1ファイルに集約しています
（詳細は後述の「ファイル構成について」を参照）。

| `src/settingsService.ts` | 個人設定・全体設定・日付ユーティリティ |
| `src/html/Index.html` | ページ全体の骨格（`<head>`／`app-shell`の構造と各パーツのinclude） |

| `tests/run.js` | 外部サービス非依存の純粋関数に対する単体テスト（Node.js, 追加依存なし） |

Drive機能は企画書5.1のホーム3カード（カレンダー／メール／リンク集）には含まれないため、
左コントロールパネルに専用の「Drive」ナビ項目を追加し、別画面として実装しています。
アプリリンク集・ToDoリストも左コントロールパネルに専用ナビ項目を持ち、ホーム画面の右サイドバーに
表示されるカード（`#card-links`／`#card-todo`）と専用ページ（`#view-links`／`#view-todo`）は
同一のDOM要素をJS側で付け替えて使い回しています（`switchView()`）。

メールタブは他と異なり、ホームのメールウィジェット（コンパクトな一覧＋ポップアップでの本文閲覧）
とは別に、**独立した2カラム画面（`Pages.html`内の`#view-mail`）** として実装しています。
ホームウィジェットのDOM要素を使い回すと、右サイドバーごと非表示になるタイミングでその子要素
（本文閲覧・作成モーダル）まで一緒に隠れてしまい、メールタブ内で本文閲覧・新規作成が機能しなく
なる問題があったため、あえて分離しています。左ナビの「メール」タブには未読件数バッジを表示します
（ヘッダーの通知ベル・メールアイコンは廃止しました）。

## ファイル構成について（ファイル数の集約）

Apps Scriptエディタへ手動で移行する運用上、ファイル数が多いほど「ファイルの作成漏れ」が起きや
すいため、機能同士の結合が弱い（=分けても実害が小さい）ものはできるだけ1ファイルへまとめています。
以前は26ファイル（TS 13 + HTML 13）に分かれていましたが、現在は13ファイル（TS 4 + HTML 8 + 型
定義ファイル`types.ts`）に集約しています。GAS側は全ファイルが単一のグローバル実行空間として
結合されるため、namespace単位・画面パーツ単位でファイルをまたいでも動作上の違いはありません。
`html/Pages.html`のように、複数の`<div id="view-X" hidden>`を1ファイルの中に自己完結したブロック
として持たせ、`Index.html`からは1回のincludeで済ませる、という構成を随所で使っています。

## ホーム画面のウィジェットシステム（配置・サイズのカスタマイズ）

カレンダー・今日の予定・メール・アプリリンク集・ToDoリストは、それぞれ独立した「ウィジェット」として扱い、
全体設定画面から次を自由に変更できます（`UserSettings.widgets`、`src/settingsService.ts`）。

- **表示/非表示**
- **配置先**（メインエリア／サイドバー）
- **大きさ**（小=1:中=2:大=3 の高さ比率でflex-growに反映）
- **表示順**（同じ配置先内での並び順）

設定画面には、メインエリア／サイドバーの2列を模した**視覚的なレイアウトエディタ**を用意しています
（`JavaScript.html` の `renderWidgetLayoutEditor()` 以下）。両列のドロップゾーンは常に同じ固定高さ
（420px）で、その中の各ウィジェットブロックは実際のダッシュボードと同じ `flex-grow` 比率
（小=1:中=2:大=3）で高さを分け合います。これにより、**どの大きさの組み合わせでも、メインエリアと
サイドバーの合計の高さは常に一致します**（実際のホーム画面でも両列は同じ高さに揃うため、それを
そのまま再現しています）。各ウィジェットはブロックとして表示され、

- ブロックをドラッグ＆ドロップすると配置先・順序が変わる
- ブロック下端の取っ手を上下にドラッグすると大きさが小→中→大の順に1段階ずつ変わり、同じ列内の
  他のブロックはflex-growにより自動的に伸縮します（一定距離ドラッグするごとに1段階変化）
- 目のアイコンで表示/非表示を切り替えられる（非表示のブロックは薄く表示されたまま編集できます）

変更はブラウザ内の一時状態としてのみ保持され、「個人設定を保存」ボタンを押すまでサーバーには
反映されません。実装上は、`data-card="calendar|today|mail|links|todo"` を持つ同一のカード要素を
`applyWidgetLayout()` が設定に応じてメインエリア（`#card-stack`）かサイドバー（`#right-sidebar`）へ
都度付け替えており、ウィジェットごとに専用のDOMを複製していません。

**PCビューのホーム画面は下方向にスクロールしません。** メインエリア・サイドバーは
`overflow:hidden` とし、各ウィジェットは割り当てられた高さぴったりに収まるよう
flex-growで比率配分されます。ウィジェット内の一覧（メール・アプリリンク等）がその高さに
収まらない場合は、ページ全体ではなく該当ウィジェット内部だけがスクロールします。
**それ以外の画面（メール／Drive／アプリリンク／ToDo／設定）はPCビューでも下方向へスクロールでき、
左のコントロールパネルとヘッダーは常に固定表示のままです**（`app-shell` を画面ちょうどの高さに
固定し、`.main-content` だけを独立したスクロール領域にすることで実現しています）。
この制約はPCビュー限定で、モバイル幅では従来通り自然な縦積み＋ページスクロールです。

## 個人用カスタムナビ項目（コントロールパネルへの自由な項目追加）

アプリリンク集（Drive・Calendar側の台帳）とは別に、個人がコントロールパネルへ好きな名前の
ショートカットボタンを自由に追加できます（`UserSettings.customNavItems`、
`src/settingsService.ts` の `sanitizeCustomNavItems`）。押すと指定したURLを
新しいタブで開くだけのシンプルな仕組みで、全体設定画面から追加・削除・並び替えができます。
表示名・URLともに個人のPropertiesServiceに保存されるため、他のユーザーには影響しません。

## カレンダーの曜日色分け・祝日名・六曜表示

ミニカレンダーの各日付セルに、次の付加情報を表示します（`getCalendarDayInfo()`、
`src/constants.ts`内の`JapaneseHoliday`/`RokuyoService`）。

- **土曜日は水色、日曜日はピンク色、祝日はライトグリーン**の背景色（CSSの`:nth-child`による
  曜日位置判定＋`.is-holiday`クラス）
- 各日に**祝日名**（該当する場合のみ）と**六曜**（先勝/友引/先負/仏滅/大安/赤口）を表示
- 祝日判定は、固定日の祝日・ハッピーマンデー（第n月曜）・春分/秋分の日（近似式）・
  振替休日・国民の休日まで現行の祝日法ルールに対応（2020/2021年のオリンピック特例日程は対象外）

> **六曜の精度について（重要な制約事項）**: 本来の六曜は太陰太陽暦（旧暦）の月+日から算出する
> 必要があり、朔（新月）のタイミングに依存します。本アプリの実行環境は外部の暦データを
> 参照できないため、`RokuyoService`（`src/constants.ts`）では基準日から6日周期で機械的にローテーションする
> **簡易的な近似値**として実装しています。旧暦の月替わりのタイミングで実際の六曜と数日程度
> ずれる場合があるため、正確な六曜が必要な用途では外部の暦データ・APIへの置き換えを
> 検討してください。

## ヘッダーの共通「戻る」「更新」ボタン

ヘッダー左に「戻る」、右に「更新」ボタンをアプリ全域で常時表示しています。「戻る」は画面遷移の
履歴（`state.viewHistory`）を1つ遡ります。「更新」は現在表示中の画面に応じて適切な再読み込み処理
（メールタブなら `getRecentMails()`、Driveなら現在のフォルダの再取得、それ以外は `loadHome()`）を
呼び分けます。各更新ボタン（ヘッダー共通のものに加え、メール・Drive・アプリリンク集の個別更新
ボタンも含む）は、押すとアイコンが回転し、処理中はボタンが無効化される「読み込み中」の演出が
入ります（`withSpinner()`、`src/html/JavaScript.html`）。

## メールタブ（2カラム表示・既読化・返信）

メールタブ（`Pages.html`内の`#view-mail`）は左に件名一覧、右に本文をインライン表示する2カラム構成です。
PCビューでは両カラムがそれぞれ独立してスクロールするため（Gmail等と同様）、右側の本文を
スクロールしても左側の件名一覧の位置は動きません。メールをクリックすると本文がその場に表示され、
同時に一覧上でも未読表示から外れます（`MailService.markRead()` が `GmailApp` 上でも既読化するため、
Gmail本体側の未読状態にも
反映されます）。ホーム画面のメールウィジェット（コンパクト表示・ポップアップでの本文閲覧）でも
同様に既読化されます。更新ボタンは `getRecentMails()` という軽量な専用エンドポイントでメール
一覧のみを再取得するため、ホーム全体を読み込み直す場合より高速に反映されます。

本文を開いたメールには「返信」ボタンがあり、返信内容を入力して送信すると `GmailThread.reply()`
によりそのスレッドへの返信としてGmail側に送信されます（宛先・件名(Re:)は自動的に設定されます）。
ホーム画面のメールウィジェットのポップアップからも同様に返信できます。

## ToDoリスト

一般的なToDoリストと同等の仕様（追加・完了チェック・削除・完了済みの一括削除）を実装しています
（`TodoService`、`src/services.ts`）。他のウィジェットと同じ仕組みで、ホーム画面での配置・大きさ
（設定画面のレイアウトエディタ）・専用タブ（左ナビの「ToDo」）に対応しています。データは個人の
`PropertiesService`にJSON配列として保存しており（最大200件）、他のユーザーとは共有されません。

## Driveタブの表示速度・ファイルを開く操作について

一覧取得時に1ファイルごと `getSharingAccess()` を呼び出していたのを廃止しました。この呼び出しは
現状のUIで使われていないにもかかわらず、ファイル数に比例してDrive APIとの往復が増え、一覧の
読み込みを遅くしていました。ファイル名をクリックすると、そのファイルをGoogle純正の画面で
新しいタブで開きます（フォルダ名クリックはこれまで通りアプリ内でそのフォルダへ移動します）。

## セットアップ手順

1. **依存パッケージのインストール**
   ```bash
   cd google-hub-app
   npm install
   ```
2. **GASプロジェクトの作成**
   ```bash
   npx clasp login
   npx clasp create --type webapp --title "Google連携統合管理アプリ" --rootDir dist
   ```
   生成された `.clasp.json` の内容を確認し、`scriptId` を控えておく（`.clasp.json` はコミット対象外）。
   `.clasp.json.example` を参考にしてください。
3. **ビルド＆プッシュ**
   ```bash
   npm run clasp:push
   ```
   `npm run build`（`clasp:push`が内部で呼び出します）は毎回 `dist/` を空にしてから再生成します
   （`scripts/clean.js`）。ソースファイルの統合・削除・リネームを行った際に、`dist/` に古いファイルが
   残ったまま `clasp push` してしまう事故を防ぐためです。
4. **Webアプリとしてデプロイ**
   - GASエディタの「デプロイ」→「ウェブアプリ」、または `npx clasp deploy`
   - `appsscript.json` の既定値は `access: MYSELF`（個人アカウント運用を前提とした最も安全な既定値）。
     社内Workspaceドメインで運用する場合は `DOMAIN` に変更してください（11.1 参照）。
5. **初回アクセス**
   - アプリ台帳（スクリプト管理）用のスプレッドシートは初回アクセス時に自動作成され、
     スクリプトプロパティ `LEDGER_SPREADSHEET_ID` に保存されます（手動作成不要）。
   - 同期対象カレンダー・メールラベル・通知設定は「全体設定」画面からいつでも変更できます。

## OAuthスコープについて（11.1 開発・セキュリティ面のベストプラクティス）

`appsscript.json` は本アプリの機能（Driveの共有設定変更・移動・名称変更、Calendarの予定操作、
Gmail閲覧・既読化・送信、スプレッドシート台帳、簡易死活監視のUrlFetchApp）に必要な最小限のスコープを
指定しています。Drive共有設定の変更・移動・名称変更はアプリ作成外のファイルにも及ぶため、
`drive.readonly` や `drive.file` では不足し、フルスコープの `drive` を使用しています。
メールをタップした際の既読化（`GmailApp.markRead()`）には読み取り専用の `gmail.readonly` では
不足するため、読み書き可能な `gmail.modify` を使用しています。メール作成・送信機能のためには
`gmail.send` を別途追加しています。**このスコープ変更（`gmail.readonly` → `gmail.modify`）により、
既存デプロイでは初回アクセス時に再認可（スコープの再承認）が必要になります。**将来的に
共有設定変更・移動機能を使わない場合は、`drive.readonly` へ絞り込むことを推奨します。

## 予定の種類（カテゴリ）と色分けについて

予定作成/編集モーダルの「予定の種類」（未設定／有給／午前半休／午後半休／ミーティング／来客対応／
出張／その他）は、追加のプロパティやシートを持たず、Google Calendarが標準で持つイベントカラー
（`CalendarEvent.setColor()`/`getColor()`、colorId "1"〜"11"）にそのまま乗せて実装しています
（`EventCategory`、`src/constants.ts`）。そのため、本アプリで設定した色分けはGoogleカレンダー本体でもそのまま
確認できます。候補を増減したい場合は `EventCategory.CATEGORIES` を編集してください。

## 制約事項・留意点（企画書 8章 準拠）

- 1回のスクリプト実行は最大6分でタイムアウトするため、`checkAllApps()` によるアプリ台帳の
  一括稼働確認は登録数が多い場合に分割実行を検討してください。
- カレンダーへのゲスト招待メール送信、メールタブからの新規作成・送信はいずれもGmail送信枠を
  消費するため、大量自動送信は避けてください。
- Google Chatとの連携は本フェーズの対象外です（将来フェーズで再検討）。
- アプリリンク集はURLを貼り付けるだけで登録する方式とし、後から名称やURLを編集する機能は
  意図的に持たせていません（誤登録は削除のみ可能）。名称はリンク先ページの`<title>`を
  自動取得します。取得できない場合はURLがそのまま名称になります。
- カレンダーをメインコンテンツの縦幅いっぱいに表示するレイアウトはPCビュー限定です
  （モバイル幅では従来通り内容に応じた高さで表示されます）。
- カレンダーの日付セルには、その日の予定タイトルを見える範囲でチップ表示します（入りきらない分は
  「他n件」とまとめて表示）。予定の編集・追加や全件の詳細確認は、従来通り日付セルをタップした際の
  ポップアップで行います（今日の予定のみ右サイドバーの「今日の予定」カードに常時表示）。

## 開発体制

企画書9章の体制（プロジェクトオーナー／ディレクター・PM／GAS開発担当／UI・UXデザイン担当／
QA担当）を踏まえ、要件整理・実装・UI設計・品質確認の観点を横断しながら実装しました。
